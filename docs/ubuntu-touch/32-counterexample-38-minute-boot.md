# 32 — 反例：有一次开机跑了 38 分钟都没卡

**日期**: 2026-09-18
**推翻了**: [`27`](27-what-a-reachable-window-shows.md) §3 和 [`30`](30-outbound-drops-before-the-queue.md)
里"这是时刻表、不是概率"的说法。

---

## 1. 现场

设备在 03:56:54 开机（同一张已知可用的 v63 镜像），到 04:33 已经 **uptime 2281 秒（38 分钟）**：

```
连续探测 60 秒：      可达 20 / 20
设备端 monitor 日志：  rndis0  RX 346876 包 / TX 406578 字节，收发包数都是 4265，同步增长
host usb0 MAC：        9e:a8:17:12:2a:76 —— 全程未变，没有任何重新枚举
```

RX 和 TX 都在涨、包数相等——**这是一条健康的双向链路，而且已经健康了 38 分钟。**

## 2. 这推翻了什么

| 之前的说法 | 现在 |
| --- | --- |
| "每次开机头 ~50 秒通，之后必卡"（[`27`](27-what-a-reachable-window-shows.md)） | **不成立**。这次 38 分钟没卡 |
| "不是概率，是时刻表"（[`27`](27-what-a-reachable-window-shows.md) §3） | **反过来了**：它确实是逐次开机不同的，我基于一次测量过度概括了 |
| "容器/netd 起来就把链路打死"（[`30`](30-outbound-drops-before-the-queue.md)） | **被这次开机削弱**。这次容器有着启动痕迹（`lxc-start` 在日志里出现 727 次），链路却是好的 |

所以我现在的诚实说法是：**有些开机卡、有些不卡，我不知道判别依据是什么。**
之前我给出的两种解释（"必然卡"和"1/4 概率"）都不对，而这次我又犯了同一类错误——
**用一次测量去定义一个规律**。

## 3. 顺带查清的一件事：SSH 不通的原因不是我的修复

这个 boot 里 8080/8081 在监听，**22 不在**。而 15:57 那次抓到的页面里 22 在监听。

rootfs 里有一个服务：

```
/etc/systemd/system/multi-user.target.wants/lxc-android-config-disable-ssh-socket.service
  -> /usr/lib/systemd/system/lxc-android-config-disable-ssh-socket.service
```

**Ubuntu Touch 自己会故意把 SSH socket 关掉**（名字很直白）。所以
[`scripts/fix-ssh-authorized-keys.sh`](../../scripts/fix-ssh-authorized-keys.sh) 把公钥和
`AuthorizedKeysFile` 都摆对了，只要这个服务还在跑，sshd 就不会监听。

也就是说：**SSH 那一步还缺一块——要 mask 掉这个服务**。这是可以提前做完的，不需要设备。

## 4. 现在在做什么

设备可达、稳定，所以挂了一个 **45 分钟长测**（`measure-link-stability.sh 45`）。
目的很直接：**看它会不会自己卡，以及卡在哪一秒**。

- 如果 45 分钟都不卡 → 这个 boot 是"好"的一类，需要用别的手段找判别依据
- 如果中途卡了 → 卡的时间点和当时的 `ip rule` / iptables 就能对上（不过这次没装 netsnap，
  所以只能记时间点，不能记现场）

无论哪种结果，都比继续猜有用。

## 5. 一个有价值的巧合

设备这次是在**断电/充电两个多小时后冷启动**的（01:35 掉线，03:56 重新出现）。
而之前卡死的几次，都是**紧接着上一次开机、由脚本连续重启**的。

我不能从两个样本下结论，但"连续重启 vs 冷启动"是一个**可以主动控制的变量**，
而且如果它成立，解释会很自然：连续重启时上一次的某些残留（userdata 里的状态、或
USB 设备侧的时序）会影响这一次。这值得作为下一个实验，而不是当作结论。

## 6. 当前的判断

| | |
| --- | --- |
| 已确认 | 出方向的包在设备队列之前被丢掉（[`30`](30-outbound-drops-before-the-queue.md)）—— 这个签名本身没被推翻 |
| 已确认 | 卡死不是每次都会发生 |
| 不知道 | 什么决定这一次卡不卡 |
| 下一步 | 先看 45 分钟长测；同时把"冷启动 vs 连续重启"做成可控实验 |
