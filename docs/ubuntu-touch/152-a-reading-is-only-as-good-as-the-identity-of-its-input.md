## 1. 一句话结论

| 问题 | 答案 |

## 2. 为什么这条闸门在这个工程里不是形式主义

### 2.1 三个各自都能成立的事实，加起来就是一个静默的空缺

* **离线读数按路径取文件。** `zl1-modem-mount.sh` 读两张候选镜像和一张 rootfs 镜像；每一个探针都点名镜像；
  `flash-boot-image.sh` 拒绝一张没和目录里 `SHA256SUMS` 对上 hash 的镜像。
* **文件名会被重建覆盖。** 这张板现在 boot 的那个镜像**就是**一个重建体，而且**保留了 v63 这个名字**。
  文件名在这个工程里是**标签**，不是身份——记录里自己写着这句：`v` 号只是产生它的那些会话的标签，
  两次不同的构建可以共用一个标签。
* **记录是手工重新生成的。** `scripts/gen-candidate-manifest.sh` 不挂在任何自动流程上，镜像目录在仓库外。

于是：**一次重建 + 没有重新记档 = 一条按路径的读数被归给了一个它没读过的文件**。这棵树里没有任何东西会注意到，
因为文件是真的、名字是对的、文档里的 hash 也是"真的"——**它只是关于另一个文件的**。

### 2.2 这是这棵树反复在找的那个形状，只是高了一层

这个工程已经在 harness 这一层写过好几次同一句话：

* 一个 fixture 落进了**它自己被测的那棵树**，而**每一条断言都看不见它**（docs 128 §9c）；
* 一条检查读 `git show HEAD:<file>`，于是**修好之后它开始自己和自己比**（docs 149）；
* 一份报告统计了**它自己的表格**，读出 34 覆盖 / 0 缺口（docs 148）。

这一条只是把它抬到了**输入**这一层：**一条读数只和它读的那个文件的身份一样可信**。
所有断言都对、所有判定都绿、而它们全都是关于**另一个文件**的——这正是那个形状最贵的样子。

## 3. 闸门：两个方向、两份记录、一张判定表

`scripts/host/zl1-artifact-manifest.sh`——只读、主机侧、**完全没有设备代码路径**（它连 `fastboot`
这个名字都不出现，harness 对出厂文件静态断言这一条）。

| 方向 | 查什么 | 为什么必须查 |
|---|---|---|
| 记录 → 盘 | 每一行的**大小**和 **sha256** | 这是记录存在的意义 |
| 盘 → 记录 | 盘上每一个 `*.img`，记录**一个字都没提**的 | **这才是读数被归错文件的那条路**：文件是真的、记录不响，其他任何东西都不会注意到 |
| 第二份记录 | 目录里的 `SHA256SUMS` 对 `manifests/` 那一张 | **两份记录可以互相矛盾**，只读一份就是只读了一半的证据 |
| 记录自己 | 有多少行、这一版解析器**读不了的行** | 读不了的行被**数出来**，不算"查过了" |

判定**不是 yes/no**：

| 状态 | 判据 | 含义 |
|---|---|---|
| `IN SYNC` | 每行大小 + sha256 都对、盘上无未登记文件、两份记录一致 | 按路径的读数是**记录所描述的那些文件**的读数 |
| `DRIFTED` | 某文件大小不符 / 同大小不同字节 / 记录读不了的行 / 两份记录不一致 | 记录**不再是这个目录的描述**；文件被点名 |
| `EXTRA` | 盘上有、记录没有 | 读数会被归错的那条路 |
| `UNREADABLE` | 表里**一行都没有** | exit 3，**什么都不主张** |
| `IN SYNC (SIZES ONLY)` | `--quick` | 它**自己说自己弱在哪** |

两个决定让它**可用**而不是变成噪音：

**① 记录里那句 `Generated by ... on <时间戳>` 被排除在外。**那一行**按设计每次重新生成都变**，
所以把它算进比较的检查**每一次都会失败**——而**一条永远失败的检查就是一条没人看的检查**
（docs 149 的同一条教训，这里是第二个变体）。断言是配着它的：fixture 里带一个**不同的**时间戳，
**仍然必须是 IN SYNC**。

**② 一行都没有的表是 `UNREADABLE`，不是"通过"。**行数为零的时候，一个报"没发现漂移"的检查是
**在一个空集上报通过**——而"我什么都没比、什么都没发现"被印成通过，正是 docs 148 点名过的那个形状。

而 `--quick` 不是"更安静的强模式"：它**只比大小**，所以一次**同大小的改动**它看不见——
**而一次同大小的改动正是"原地重建"的形状**。harness 把这一点**断言**了：同一个同大小变异，
两种模式必须**给出不同答案**。如果哪天两种模式一致，那就是其中一种没在做它声称的事。

## 4. 第一次真实读数

```
  rows in the table: 90
  verified by size AND sha256: 90 rows
  drifted: 0   missing: 0   unreadable rows: 0
  (no .img on disk is missing from the record)
  entries in it: 90
  (the two records agree on every name they share)
== verdict: IN SYNC
```

**90 张镜像、90 行按大小和 sha256 都对上、盘上没有文件是记录不知道的、两份记录在每一个共同名字上一致。**
所以上一页那条 modem 读数（以及这一整棵树里所有按路径取镜像的读数）确实是**记录所描述的那些文件**的读数——
这句话以前**是假设**，现在是一条读数。

## 5. 第二个半边：让读数**带着它的输入**走

闸门查的是"记录和盘一致"；它**不**能回答"**这一次运行**读的是哪一次构建"。所以 modem 那条仪器现在把
**它读的每一个镜像的 sha256 和大小**印两遍：一次在头部（和路径一起），一次**紧挨着判定**。

```
  read from:
    ac0dd8619c05763c0ec54e780c6bcfe89f469a05f9f5d4ad825ed13623d0ed89  .../halium-boot-zl1-v63-rebuilt.img
    ec1d52fa36b37893b840e30a60dbbda4a54b0058bf258ab1b1d20ba8508142f8  .../android-system-zl1-halium-candidate.img
    10af178c8d8e7b4e2f94a6526dfecc0bba5ca8d41dd6a24ed29095d43f749375  .../rootfs-24.04-2.x-arm64-android9plus-zl1-host.img
```

理由不是装饰：**一份没有输入身份的存档判定，是一句关于无名文件的话**。等目录往前走了一步，
后读的人需要知道的正是这三个 hash。这是 docs 149 那条规则（"对着一个确定的修订去证明"）**往下挪了一层**。

## 6. 顺带查出的三个真缺陷

### 6.1 `--quiet` 做的是它自己使用说明的**反面**，而且**没有任何断言提到过它**

使用说明写的是"只印判定，不印读数"。第一版的闸门是：

```sh
say() { [ "$QUIET" = 1 ] && [ -n "${1:-}" ] && return 0; printf '%s\n' "$*"; }
```

于是 `--quiet` 下：**判定（非空）被压掉，空行（空）被印出来**。实测输出是**一串空行**。
**这是一个被写进手册、却没有任何断言提过的选项**——所以它坏了好几天，
而这棵树里**每一条**"检查必须能报出它要说的话"的教训在这里都成立：
一个没有断言的选项不是功能，是**承诺**。

修的时候**修了两次**，因为第一遍只堵了一半：判定那一半靠 `SHOW` 标志，而**读数里有一半根本不经过 `say`**
——它们是 `grep | sed` 和 `awk` 直接写 stdout 的，从来就没碰到闸门。现在所有直写 stdout 的打印器
都过同一个门（`quiet()`）。**这正是"只堵住你看见的那条路"的形状**：一个 `--quiet` 压掉一部分、
印出另一部分，比一个什么都印的 `--quiet` **更坏**，因为它的输出**看起来像一个答案**。

现在有一个小节**真的跑它**：判定必须在、读数必须不在、而且那一块**必须长到不像被截断的尾巴**
（一个"判定也被压掉"的运行会是一次**没有输出的干净退出**，那是所有形状里最危险的一种）。

### 6.2 页面点名一个脚本，就**欠**它一句 `--help`

这一页的正文里点了 `flash-boot-image.sh` 的名字（它拒绝一张没和 `SHA256SUMS` 对上的镜像，正好是本文的例子）。
**点名是有代价的**：这棵树有一条规则（docs 113）——**页面告诉你去跑的每一个脚本，都必须能自己讲清自己**，
而那正是这条规则在起作用。它**做不到**：

```
$ bash scripts/flash-boot-image.sh --help
FAIL: image missing: --help
```

`--help` 被当成了**镜像名**，然后在预检里死掉。修法是这棵树里其他每个脚本都在用的那个形状
（`case ... --help|-h)` + 打印自己的头部）。有意思的是**这一条是被那次点名逼出来的**：
在页面提到它之前，没有任何东西要求它答题。

（顺带一个真的坑：第一版写成 `if [[ ... == "--help" ]]`，**能跑、能印、rc=0**——而 sweep 的**静态闸门**
仍然判它"根本不答 `--help`"，因为那个闸门找的是 `case` 的那个字面形状。
**它先读你会不会答题，然后再决定敢不敢跑你**——这个顺序是对的，因为在一个会 flash 的脚本上试错，
代价不是红一条断言。）

### 6.3 一个"比对了零行"的通过

见 §3 的第 ② 条。这一条是**设计时**就堵住的（第一次运行就有一条断言盯着它），
写在这里是因为它是这一页的同一条原则：**一份印不出缺口的报告，和一份没有缺口的报告，读起来一样。**

## 7. 这一篇**不**证明什么

* **不证明盘上的镜像是"正确的"构建。**它证明的是**记录和盘一致**。如果两边一起错了
  （比如一次重建之后**重新记了档**，而新记录没有回头去改引用那个 hash 的文档），这道闸门会报 IN SYNC——
  而文档里的 hash 仍然是旧的。**闸门管的是记录与盘之间，不是文档与记录之间**；后者是下一次
  `grep` 那个 hash 的人的工作，脚本的判定里明说了这一点并给出下一步。
* **不证明那个记录是完整的。**它只检查**记录点到的文件**和**盘上没被记录点到的 `.img`**。
  一张被删掉的镜像会让对应行变成 `MISSING`——但如果**记录里本来就没有那一行、盘上也没有那个文件**，
  这里没有任何东西会知道它曾经存在过。
* **不证明 modem 那条仪器在设备上是对的。**它读的仍然是**镜像文件**，设备侧那句 `ls` 仍然是确认。
  §5 只是让它的读数**能被追溯到输入**。
* **不证明 `--quiet` 从此不会坏。**它证明的是**现在有一个断言在跑它**——而这一页之所以要写下来，
  正因为"有一个断言"和"有一个功能"是两件事，而这次坏掉的正是没有断言的那一半。

## 8. 设备状态与下一步

整轮**没有动设备**：没有挂载、没有写镜像、没有 flash、没有发过一条设备命令。
设备仍在 **fastboot**（序列号 `33e80afe`，`battery-soc-ok: no`）。这一轮唯一一次碰设备是 `lsusb` 和
battery gate 那条**只读**的采样（仍是 `FLAT WITHIN NOISE`，与上一轮同一读数——**什么都没变**）。

想重跑这一页的任何一条读数，**一个设备都不需要**：

```
bash scripts/host/zl1-artifact-manifest.sh              # 记录和盘一致吗（90 行，约 8 GB 哈希）
bash scripts/host/zl1-artifact-manifest.sh --quick       # 只比大小，并说自己弱在哪
```

`bash scripts/host/zl1-battery-gate.sh --samples 9 --interval 60`；

两个散热修复和指纹存储目录会在硬件上第一次真的跑起来。
