## 2. 一个用法文本是怎么坏的

`--help` 是这个仓库里唯一**永远安全**的命令，而这个项目的头**就是手册**：带 Usage 行、退出码、以及
为什么这么做。所以一个打不出自己头的工具，就是 [`107`](107-the-instruments-that-cannot-report-are-not-armed.md)
那一族的仪器。

坏掉的形状有两种，而第二种比截断更难发现：

```
sed -n '2,53p' "$0"          # 头 52 行：正好。头 54 行：最后两行静默消失
sed -n '2,84p' "$0"          # 头 71 行（到第 72 行结束）：多打出 12 行 —— 而这 12 行是代码
```

第二种在多打出来的那一边会打印**脚本自己的变量赋值**，包括它要连的 SSH 目标。它不会报错、不会退出非零，
看起来只是"usage 长了一点"。

判据是这一轮定的：**头里写了 `Usage:` 行，就必须打得出来。** 8 个脚本违反它——它们的 usage 打印是
`*)` 分支（未知参数 → 打印头 → 退 1），于是 `--help` 也走了那条路。打印手册不是错误，所以这些补的是
显式的 `--help|-h) … exit 0`，而 `*)` 保持原样（一个"没有参数"调用仍然得到这个脚本自己的退出码）。

## 3. 守卫：一条自我维护的规则

`scripts/host/zl1-cli-usage-selftest.sh` 的覆盖集**不是手写的**，而是从 `zl1-health-check.sh` 里
grep 出来的：**这一页告诉一个人去跑的每一个脚本**。这条规则的意义在于它自己维护自己——往健康检查里加一步，
它的脚本就自动进入扫描，不用靠下一个作者记得来改这个文件。

三件事：

1. **每个被点名的脚本**：`--help` 退 0、输出非空、**每一行都以 `#` 开头**、并且**逐字等于**这个文件真正的
   头（期望值是 harness 自己用同一条 awk 算出来的，不是从被测脚本读来的——那会变成自比较）。
   头里有 `Usage:` 的，再断言那行还在。
2. **性质测试**：给每个头的副本**末尾插一行注释**，要求打印出来的行数**正好 +1**。硬编码行号过不了。
   这是核心——它不在乎脚本怎么打印，只问"头变长时输出会不会跟着长"。
3. **全树的两条不变量**：`scripts/` 下不再有 `sed -n 'A,Bp' "$0"`（这条 grep **排除 harness 自己**，
   因为那个模式在它源码里是个字符串，不排除的话它永远能找到一处、也就是自己；还**限定 `*.sh`**，
   见下）；以及**每个 `*.sh` 都可执行**。

   限定 `*.sh` 是这条检在写完当天就被它自己教的一课：第一次全量运行时它报了一个"还有一处固定行号"，
   而那"一处"是 **`scripts/README.md`**——我刚写进去的、**描述这个缺陷**的那一行。也就是说：

   > **按缺陷的形状去 grep，会命中"说出这个形状"的那段文字。**

   和排除自己那条是同一种事故（模式出现在文档里而不是代码里），修法也一样：把范围收到真正能犯这个错的
   东西上（可执行的 `*.sh`）。README 不能打印任何东西，它犯不了这个错。

   **同一天里，同一段代码教了两次同样的课**——第二次是覆盖集本身，见 §3.1。

### 3.1 同一天里的第二次：覆盖集自己漏了 4 个脚本

这一轮的最后一步是把 §5 里那些数字改准，于是我去数"健康检查到底点了几个名"。用真实 grep
（`sh` 里的 GNU grep，不是交互 shell 里那个包装）数出来 **24**，而 harness 报的是 **28**——多出来的 4 个
是它自己从**文件名**解析出来的。回头一看，那一页有两种写法：

```
always "       zl1-boot-address-selftest.sh, 24 checks, runs the real script against synthetic netwatch"
always "       Its parsers are pre-verifiable without the device and without a hand: scripts/host/"
always "       zl1-orientation-axes-selftest.sh"
```

第一行是**光秃秃的文件名**；第二、三行是**一条路径被折行切开**（那一页的排版宽度就是原因）。只认
`scripts/…` 形式的提取器两头都看不见，于是：

* §2 的覆盖集少了 4 个脚本（三个 harness 加这一页自己）；
* §4d 的防漂移守卫扫描一直只查了它点名的 **7** 个 harness，却报告"全都好"——而它点的是 **10** 个；
* 那 4 个脚本的 `--help` 修复，**当时是被"什么都没有"覆盖着的**——正是 §3 里那条"修复不能是这一轮唯一
  没有守卫的东西"要避免的局面。

修法是把两种形状都读进来，并且**把两个数字分开打印**（`24 came from a path` / `4 from a bare
basename`），这样一个数字塌成零的时候另一个会立刻露出来。文件名解析要求**唯一**：`zl1-debug-net.sh`
在这棵树里根本不存在（它是设备侧 v63 的产物），那不是遗漏而是事实；真出现两个同名文件时会报红，而不是
随便挑一个。

这一节留下的规则和前两节是同一条，只是换了一层：

> **一个"这一页说了什么"的提取器，它的失败方式和它要防的缺陷是同一个：静默地少看见一些东西。**

**而且这一条必须用一个"反向变异"来证明。** M7 把副本里 thermal 那条路径也改成折行的样子，要求 harness
**保持绿**（98 检查，一个不少）；M7b 拿同一个副本、换上**改回只认路径**的提取器，要求它**变红**。两次都
如预期（§5）。没有 M7b，M7 什么也没证明——*一个 no-op 之后照样是绿的。*

### 3.2 同一规则再上一层（§4d）

健康检查给每个 harness 手写检查条数，`110` 记过其中一个腐坏而没人发现。修法是让每个 harness 自己校验引用
——但**没有人校验这件事本身**。所以 4d 静态地扫：健康检查点名的每一个 `*-selftest.sh` 必须带着那条防漂移
守卫（`HEALTH="$HERE/zl1-health-check.sh"`）。

它第一次运行就红了两条：

* 它报了**自己**——这个 harness 的 `HEALTH` 用的是 `$ROOT/...`，因为 `--sweep-root` 要能指向别处。修法不
  是放宽检查，而是让 repo 那一条走和所有兄弟一样的赋值。
* 它报了 ``zl1-orientation-axes-selftest.sh``——健康检查点了它的名却**没给数字**，而它自己也没有守卫。
  这是同一个缺陷的"数字整个缺失"版：读者分不出这是 12 条检查的 harness 还是 200 条的。

**但"$n 个 harness"这个数字本身是错的**，而且错法和它要防的缺陷一样：`4d` 当时是**自己去 grep 那一页**
（正则要求路径写在同一行），所以它查了 7 个、报"全都好"，而那一页点名的是 10 个（§3.1）。现在它读的是
§1 已经算好的"这一页点名的"集合，两个小节看的是同一个集合——这才是这条规则的本意。

数字和守卫两件事**分开管**：4d 只查守卫在不在；数字对不上由每个 harness 自己那条报红。分工是刻意的——
harness 自己知道本次运行的条数，别的文件猜不出来。

## 4. 顺带更正的三处：同一个头里，几个把修复说小了的数字

这一轮是从 `install-cpufreq-governor.sh` 的头开始的，它里面有三个数在别处已经被更正过：

| 头里原来写的 | 实际是 | 依据 |
|---|---|---|
| keeper **烧 6.6% 的一个核** | **整整一个核**（停 0.87 / 跑 1.84，即 4 核 SoC 的约 24%） | `72` §4b。6.6% 是**只算 keeper 自己那个 `/bin/sh` 进程的 ticks** 得到的；而它真正贵的活是**别人替它干的**——`systemctl` 是子进程，`daemon-reload` 是 systemd（pid 1）执行的，两者都不记在它头上 |
| **容器**用了 3.70/3.87 GB | **整台手机** | `87`。这个内核没开 `CONFIG_MEMCG`、rootfs 上没有 `lxcfs`，容器里的 `free` 读的是宿主机的 `/proc/meminfo` |
| 内核态占掉**一半**的 CPU（59%） | **撤回：那是 `iowait`** | `72` §4b。~~一个 20 s `/proc/stat` delta: user 16.9% / idle 24.1% / 其余 59%~~ ——`iowait` 是**等待**，不是在算；按 user+sys 重量，整机忙 **0.87 个核** |

前两处都错在**同一个方向**：把发烫修复说得比实际小。而这是一个人**做决定之前**唯一会读的那份文件——因为
它要决定的是"要不要为了省几个百分点去杀一个进程、并且承担丢掉地址的风险"。旧数字让这个交易看起来不值得，
而真实收益是它的约 15 倍。第三处是反方向的：它凭空多出半台机器的负载。它留下那条规则——**这台设备上永远
不要用 `busy = (total-idle)/total`**，要分开看 `user` 和 `sys`（`iowait` 是等待，不是计算）。

这三处更正**本身就是**触发这一轮的引信：头从 67 行长到 82 行——如果 `--help` 还是 `2,68`，这次更正就会
在 `--help` 里被静默截掉。性质测试（§3 第 2 条）就是为这一刻存在的。

## 5. 离线验证：98 检查，六次"必须失败"、一次"必须保持绿"

`scripts/host/zl1-cli-usage-selftest.sh`，覆盖集 **45 个脚本**（那一页点名 28：24 个路径 + 4 个文件名；这一轮转换的 17 个）。

| 变异 | 基线与结果（基线 **98 pass / 0 fail**，rc=0） |
|---|---|
| M1 把一个被点名的脚本改回固定行号（`2,46p`） | rc=1，96 pass / **3 fail** —— 性质测试（"多打 0 行"）、全树 grep、以及**它自己那条引用** |
| M2 删掉一个被点名脚本的 `--help` 分支 | rc=1，95 pass / **2 fail** —— "答不出 `--help` 却头里有 `Usage:`" + 引用计数 |
| M3 让头部打印**少最后一行**（模拟截断） | rc=1，96 pass / **2 fail** —— "打出了不是注释的行"（打印的是代码）+ 性质测试 |
| M4 让头部打印成**代码**（去掉 `#`） | rc=1，95 pass / **2 fail** —— 同上 |
| M5 去掉一个被点名脚本的可执行位 | rc=1，97 pass / **1 fail** |
| M6 在**覆盖集之外**新写一个固定行号的脚本 | rc=1，97 pass / **1 fail** —— 全树那条 grep |
| **M7** 把那一页里 thermal 的路径也**折行切开**（它今天对别人就是这个样子） | rc=0，**98 pass / 0 fail** —— 这是**必须绿**的那一次：路径被切开时脚本不许掉出扫描 |
| **M7b** 同一个副本，换成**改回只认路径**的提取器 | rc=1，90 pass / **1 fail** —— 28 掉到 24，是**它自己那条引用**把它抓出来的（§3.1） |

前六次全部 rc=1，每一次的失败都**指名道姓**（上面每条都附了 harness 自己的原话）。M7 是唯一一次
"绿就是通过"的，而它的意义全在 M7b 上：同一棵树、改回旧提取器就红。**没有 M7b，M7 什么也没证明。**
原始输出在 `docs/ubuntu-touch/evidence/cli-usage-mutations-2026-09-23.log`。

外加**引用链**那一对，两者必须让**不同**的文件报红：

* **C1** 把副本里的健康检查对 thermal 的引用改成 `999 checks` → **thermal harness 自己报红**（rc=1，
  44 pass / 1 fail：`the health check cites 999 checks, but this harness has 45 -- fix
  host/zl1-health-check.sh`），而**同一个副本**上的 usage harness 保持绿（98 pass / 0 fail）——分工正确。
* **C2** 把 thermal harness 的守卫改成指向别的文件 → usage harness 的 4d 报红（rc=1，97 pass / 1 fail：
  `these named harnesses cannot check their own citation: zl1-thermal-selftest.sh`）。

M1/M2/M4/M7b 里 `pass` 的总数会变，于是**harness 自己那条引用校验也跟着红**——这是真的，不是噪声：
那条检查比的是"健康检查里写的 98"和"这一轮跑出来的总数"，而变异改变了总数。所以它在这里报红是**正确
的行为**（检查是活的），但它也提醒一件事：这条检查的读数只有在树是干净的时候才有意义。

M6 值得单独记一段，因为它**第一次的写法根本做不到**。上一版计划是"把一个已经在覆盖集之外的脚本改回
固定行号"，而真去写的时候 assert 直接失败：**全树带 `awk` 头的脚本，一个不落，全都在覆盖集里**
——覆盖集是"健康检查点名的 + 这一轮转换的"，而后者的定义就是这一轮动过的那些。所以那个变异没有任何对象
可改。改写成"**新写一个**这样的小脚本"之后它才真的能红——而这也才是这条不变量真正要防的东西：一个**将来**
的、没人手工跑过的阶段机器。

这与上一轮同一位置记的那条是同一件事：那次 `s.replace('exit 0', …)` 没匹配到、变异静默地变成"复制一份
一模一样的树"，跑出来是绿的。所以这次每一步变异都先 `assert` 自己落地了。*一个什么也没改的变异，和一个
什么也测不到的检查是同一个东西。*

## 6. 这一轮自己踩的坑，以及它留下的规则

扫描是先在 shell 里手写循环跑出来的，那版循环**没有**静态闸门——它在**每一个** `scripts/*.sh` 上跑了
`--help`，包括**没有处理器**的脚本。大多数只是拒绝；但：

* `scripts/hybris-shims/make-lsc-wrapper.sh --help` **把它的输出文件写了出来**；
* `scripts/hybris-shims/build-hybris-shims.sh --help` 跑了一次链接器。

没有造成损坏：重新生成的 `lsc-wrapper.zl1` 与提交版本**逐字节相同**（sha256 `f3e1b842…`，生成器是确定性的）。
但这只是运气。所以 harness 的 §2 里那道闸门是**先读再跑**：只执行它**已经看到** `--help|-h)` 分支的脚本。

> **一条扫描如果会执行东西，第一件事是读出哪些是它被允许执行的。**

这条规则写进了 harness 的头部，连同这次事故的细节——因为"这台设备在 EDL、脚本里有刷机工具"这句话不是背景，
它是这条闸门存在的理由。

**同一轮里还有一次"我自己的量尺不是它用的那把"。** 我在交互 shell 里手测"路径提取器能找到几个名字"，
得到 `24`；harness 报 `28`。差的那 4 个我一开始以为是"折行切开"，就去量"join 之后能多找到几个"——量出来
是 `0`，于是差点写下"join 没用"。真相是：**我交互 shell 里的 `grep` 是个包装函数**（这个环境里它被换成
了另一个实现），它对 `(^|…)` 这种正则的行为和 harness 实际调用的 GNU grep **不一样**。把同一条命令包进
`sh -c` 之后，两个数字才一致。

> **验一个 harness 的读数，要用 harness 用的那把量尺（`sh -c`），不要用交互 shell 里的同名命令。**

写下来是因为它和这一篇的主题是同一件事：一个数字看起来是"环境的事实"，其实可能只是"我这把尺子的事实"。
（§3.1 的结论没有因此变化——真正把 4 个名字捞回来的是**文件名那一支**，折行那一支今天贡献 0，harness 里
因此没有留 join，而是直接读原文件。）

## 7. 这一篇**不**证明什么

* **不证明设备上任何一个脚本的 `--help` 是好的。** 设备没跑过：这一轮全部在主机上。设备侧的用法文本
  在设备回来后第一次跑就会自己现出原形，而那时读到的是同一份头。
* **不证明全树的用法文本都对。** 全树 94 个脚本头里有 `Usage:` 行，其中 **49 个**（都在覆盖集之外）仍然
  答不出 `--help`——它们是历史阶段机器（备份、刷机、build 脚本）。harness 把**这个数字报出来**，故意不
  要求它为零：要求一个从不手工运行的脚本答 `--help` 是把风格当正确性。覆盖集是"这一页告诉你去跑的"，
  那是能自动维护、也真正重要的那一条界。
* **不证明覆盖集就是"这一页告诉人去跑的全部"。** 它是从那一页的**文本**里读出来的名字，而文本不是契约：
  一个在这一页里用散文提到、但没写成 `*.sh` 的脚本不会被覆盖；反过来说，**那 17 个 extras 是手写的**
  ——手写的清单正是这个仓库反复记的会腐坏的东西（`110`）。它今天能自动维护的只有"那一页点名的"那一半。
* **不证明发烫解决了。** 两条主要成因（keeper 烧满一个核、四个核钉在 `performance`）都还没在设备上装。
  这一轮更正的是**关于它们的记录**，不是它们本身。
