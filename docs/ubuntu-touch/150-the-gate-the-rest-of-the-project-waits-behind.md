# 150 — 整个工程剩下的一切都压在一次启动上，而这一次启动压在两个从来没人读过的变量上

**日期**: 2026-09-24
**状态**: 本轮**没有碰设备**（只读了两次 `fastboot getvar`，是问句不是写操作）。设备仍在 fastboot，
序列号 `33e80afe`，`battery-soc-ok: no`。这一页新增的是**那个闸门自己的仪器**：
`scripts/host/zl1-battery-gate.sh`（只读、主机侧）与它的 harness（**92 项**）。

**为什么值得单独一页**: 这个工程剩下的**每一条**——两个散热修复、指纹存储目录、modem、摄像头、
方向那个 x/y 交换——都要一次启动，而那次启动要一个数：**这块电池能不能撑住开机**。
而**这棵树里没有任何脚本读过它**：`grep -rn battery-soc-ok scripts/` **一条也不匹配**。
也就是说，**错了代价最大的那个决定，一直在用散文做**——这正是本工程反复在写的那个形状。

## 1. 一句话结论

| 问题 | 答案 |
|---|---|
| 为什么需要它？ | 因为**剩下的一切都压在一次启动上**，而那次启动压在一个数上。而这个数**没有任何仪器**：这棵树里 `battery-soc-ok` 一次都没出现过 |
| 这块电池由谁描述？ | **只有两个变量**：`battery-voltage` 和 `battery-soc-ok`。**没有电流、没有充电状态、没有充电速率**——所以"它在充吗"这个问题，硬件只肯用一个数间接回答 |
| 那个数的单位是什么？ | **微伏**。`2773000` 是 **2.773 V**。一个拿这个原始值去和"毫伏阈值"比的脚本**错 1000 倍**——而这棵树已经因为同类错误吃过一次（[`104`](104-the-camera-app-instrument-measured-in-the-wrong-unit.md)：一个速率被印成 100 倍的单位，于是 `B >= 8` 变成了 0.08/s） |
| 那些数是怎么读的？ | 采样 N 次，而且**不是**拿一个阈值去卡一个数，而是**一张判定表**：`soc-ok: yes` 就是 `CAN-BOOT`（**LK 自己的回答**，两个方向上都压过算术）；**最后**一个读数比**前面**那批确立的范围高出/低出 `--noise-mv`，才是 `CHARGING`/`DISCHARGING`；比它小就是 `FLAT WITHIN NOISE` |
| 为什么比较的是"最后一个读数 vs 前面的范围"，而不是"首末之差"？ | 因为**首末之差会把噪声读成斜率，而这个脚本的第一版就是这样**（§3）。测出来：一个 4 秒窗口里 2.921 V → 2.810 V，它把 **111 mV** 说成"放电"，而那个窗口**自己的散布就是 111 mV**——趋势被自己的散布完全解释掉了 |
| 三个"拒绝"是什么？ | ① **一个样本不是结论**（两块样本给方向，而**没有东西能把它和噪声分开**）；② **残缺的读不是读**（少了一个样本就 `UNREADABLE`，**不**在活下来的样本上算斜率）；③ **抽出来不是数字的，一律在算术之前拦住**（因为 **bash 把空操作数读成 0**） |
| 第三条为什么会真的发生？ | 因为**它真的发生了**。第一版用 `sed -n '$d'` 抽"前面的读数"——**自动打印被抑制时，单独的 `d` 什么都不打印**——那个空字符串进了算术就是 0，于是**一个平的窗口印出了 `CHARGING`，还描述了 2847 mV 的"上升"**（§4） |
| 噪声有多大？ | **148 mV**，跨着一个没变的电池的三次连续采样（2.773–2.921 V）。也就是**比任何值得行动的趋势都宽**——所以 `--samples` 有 **3** 的下限，而且**散布**和**趋势**印在同一屏上 |
| USB 口为什么要印出来？ | 因为**它是答案的一部分**。"这个口没有净充电"和"这块电池死了"是**两个不同的断言**，而单个口上的一个窗口**只支持前一个**。分开它们的那次比较是**换一个充电器再来一个窗口** |
| 有没有改变做法的设备事实？ | **两条，都是从 `getvar all` 读出来的、都印在需要它们的那个拒绝里**：`off-mode-charge:0`（**关机时不充电**——把充电器插到关机的 zl1 上，它会**开机**。所以"关机放着充一晚"在这里**是错的**，而这恰好是任何人第一个会试的办法）和 `charger-screen-enabled:0`（**没有充电画面**——电量低到开不了机时它就是**纯黑屏、没有任何指示灯**，所以黑屏**不是**设备坏了的证据） |
| 设备是怎么认的？ | **序列号前缀 `33e80afe`，从来不用裸 USB id**。那台无关的小米（`4a2fe00b`，产物串 `MI 4LTE`）**就挂在这条总线上**，脚本把它**按序列号报出来并忽略** |
| 它会不会动设备？ | **不会**，而且这是**静态断言**：出厂文件里没有 `fastboot flash/reboot/erase/boot/oem/format/update`、没有 `dd if=`、没有 `> /dev/block`；那三个下载器工具名**确实出现过**，但**每一处都在禁止它的那句话里**——按名字逐个检查，因为**grep 一个缺陷的形状，也会匹配到点名它的散文**（这棵树在 README 上已经吃过这一记） |
| 那首次运行还找出什么？ | **第三个缺陷，而且是靠"拒绝"而不是靠"回答"找出来的**：`MODE` 留成了空串，于是"总线上没有设备"那条分支**根本到不了**——最常见的那个拒绝印的是"检查没有给出答案"的兜底，而那两条 `off-mode-charge` 事实**从来没到过操作者手里**（§5） |
| 现在的读数是什么？ | `soc-ok: no`，`FLAT WITHIN NOISE`：**既不能说电池死了，也不能说它在充**。分开它们的是**换墙充 + 更长的窗口** |
| 这一轮的离线结论？ | 家族 **33 个 harness / 4555 检查 / 全绿**，仓库自指纹未变（450 个 tracked 文件前后哈希一致） |

## 2. 那张表，和它为什么不能是一个阈值

```
soc-ok: yes @ 任一采样              -> CAN-BOOT     LK 自己说这块电池可以
最后一个读数 比 前面那批的范围 高出 >= --noise-mv  -> CHARGING     这个口在赢
最后一个读数 比 前面那批的范围 低出 >= --noise-mv  -> DISCHARGING  这个口在输
其他                                -> FLAT WITHIN NOISE  不是方向
```

三条设计理由，每条都对应一个真实的误判：

1. **`soc-ok` 压过算术，两个方向都是。** 它是 LK 说"我会让你开机"，60 秒的斜率压不过它。
   反过来，`soc-ok: no` 也**不能**被一个上升的窗口推翻——那只能说"在赢"，不能说"已经够了"。
2. **判方向要拿最后一个读数去撞前面那批的范围。** 首末之差有个致命问题：`min <= first,last <= max`，
   所以 `band >= |trend|` **恒成立**——任何首末之差都**至多等于**窗口自己的散布。
   第一版正是因此把 111 mV 的散布报成了 111 mV 的"下降"。
3. **门槛是调用者的**（`--noise-mv`，默认 100）。harness 用同一个 fixture 跑两次、
   只改这个门槛，一次 `CHARGING` 一次 `FLAT`——**证明决定结果是这个数、而不是别的什么**。

## 3. 两个真的发生过的缺陷，被留成了 mutation

mutation 只有在**它能改动出厂文件**时才算 mutation；这两条都改得动，而且两条都真的发生过：

**（a）首末之差的比较。** fixture 是**窗口结束在"前面的最小值"上**（`2.921, 2.810, 2.810`）——
按新规则，最后一个读数**没有离开**前面的范围（`BELOW = 0`），是 `FLAT`；
按旧规则，首末之差 110 mV ≥ 门槛，是 `DISCHARGING`。
**这两个规则在这个 fixture 上必须给出不同答案**，否则 mutation 什么也没证明——
这就是为什么不能用那个"平的"fixture：在它上面两条规则都说是平的。

**（b）抽空的 `$d`。** 把 `sed '$d'` 换成 `sed -n '$d'`，脚本必须印 `UNREADABLE` 而**不是**结论，
并且把理由说清楚（`bash 把空操作数读成 ZERO`），这样它**不能被误当成一次测量**。

**（c）单位折了。** 把 `NOISE_UV=$(( NOISE_MV * 1000 ))` 改成 `NOISE_UV=$NOISE_MV`，
门槛就变成 100 **微伏** = 0.1 mV。fixture 是 **1 mV** 的漂移（`3.000000, 3.000000, 3.001000`）：
正确单位下远低于 100 mV 门槛（`FLAT`），折了单位之后它"越过"了门槛（`CHARGING`）。
**这个 mutation 的存在理由**：单位错误在这棵树里已经发生过一次，而它**看起来完全正常**。

## 4. 三个"拒绝"，和它们各自拦下的是什么

| 拒绝 | 拦下的误判 | 怎么印出来 |
|---|---|---|
| `--samples` 下限 3 | 两块样本给一个**分不开噪声的方向** | 拒绝时说出理由：这块 LK 自己的散布**比值得行动的趋势还宽** |
| 残缺的读 = `UNREADABLE`（exit 3） | **在活下来的样本上算趋势**——那是链路读数，不是电池读数 | 说出"3 个里回来 2 个"，并**一个结论都不印** |
| 抽出来不是数字 | **bash 把空操作数读成 0**，于是不是失败而是**凭空造出一个读数** | `UNREADABLE` + 点名是**本脚本自己的抽取缺陷**，免得被当成测量 |

第二条和第三条的区别值得记住：第二条是**设备**没回答，第三条是**脚本**没读对。
两个都不许变成结论，但**它们不是同一件事**，所以印的话不一样。

## 5. 首次运行靠"拒绝"找出的第三个缺陷

`MODE` 初始值留空，而 `case` 里比的是字符串 `absent`：

```sh
MODE=""
for d in /sys/bus/usb/devices/*/; do ... MODE=present; break; esac; done
...
case "$MODE" in ... absent) <印那两条 off-mode-charge 事实> ;; esac   # 永远到不了
```

于是**最常见的那个拒绝**（设备不在总线上——也正是电池没电时的样子）走的是
`*)` 兜底，印 `the device-mode check produced no answer at all`，
而那两条**会改变做法**的事实（`off-mode-charge:0`、`charger-screen-enabled:0`）**一次都没印出来**。

**它是怎么被发现的**：harness 的断言要那两句话，而得到的是兜底文本。
**兜底本身救了它一次**——如果兜底是"静默通过"或者"当成 absent"，这条分支就永远不会有人知道它是死的。
这正是这棵树一直在写的那件事：**报不出自己存在理由的仪器，比没有仪器更坏**。

  分开它们需要**换一个充电器再采一个窗口**——这正是脚本印出来的那个下一步，

- 我明确**不建议**用"关机充电"来试：`off-mode-charge:0`，它关不了机充电，插上就开机。
