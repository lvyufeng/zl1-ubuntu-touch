## 1. 一句话结论

| 问题 | 答案 |

## 2. 第一个问题：那个数字一直是手打的

`docs/ubuntu-touch/124` 第 25 行逐字写着：

```
| 家族全量跑呢？ | **18 个 harness / 1979 检查 / 全绿**（本页写完时是 1967；125 之后 runbook harness 90 → 95；
126 之后 loc-fp 195 → 200、fp-store-dir 131 → 137，即 1990；127 之后 runbook harness 95 → 118、
meta-harness 124 → 125，即 2014；128 之后 heat-chain harness 107 → 159，即 2066）
```

括号里那一串是**每一次都要重新算一遍**的账。它每一步都对——而它存在的理由，恰恰是**没有一样东西
能替它算**。`110` 已经把这个缺陷族写清楚了：健康检查给每个 harness 标了一个手打的检查数，其中一个
过期了很久没人发现，修法是让**每个 harness 自己检查那条引用**（`zl1-cli-usage-selftest.sh` 第 4d 节
现在还会静态地要求"被这一页点名的 harness 必须带那条自查"）。

**但那套机制只覆盖"某个 harness 的数字"，不覆盖"整个家族的数字"。** 后者一直没有工具，
所以它每一轮都被重算、重抄、并且**只在有人想起它的时候**才更新。

现在它是：

```sh
bash scripts/host/zl1-selftest-family.sh
...
== the repository is unchanged (N tracked files hashed before and after, no new file)
== 19 harnesses run, 19 green, 0 not green, 2155 checks, 0 failing
== verdict: all green
```

那个 `2155` 是**加法**：每个 harness 自己印的 `pass=N fail=M` 被读回来，`N+M` 相加。它和
4d 节里那些**每条引用的自查用的是同一个算术**，所以"家族总数"和"单条引用"不会因为两套约定而分家。

## 3. 第二个问题：没有一条断言能看见"这棵树被改了"

`128` §5 记的那件事，形状是这样的：

* 那个 harness 把假仓库的 `scripts/device` 做成**指向真目录的符号链接**（理由正当：链要推的是**真的**
  那个设备脚本，不是替身）；
* 然后它穿过那个链接 `mkdir -p`（静默成功）并 `>` 写自己的夹具；
* 于是**仓库里那台 409 行的仪器被换成了 1 行注释**；
* 而**它自己那 151 条断言全绿**。

这件事**不可能**被那个文件里的断言发现，因为那些断言全都在问"被测脚本的行为对不对"。这是一个
**关于仓库的事实**。`128` 给那一个 harness 加了一条局部检查（对自己伤害的那一个文件前后取哈希），
并且在自己的 §6 里**明确写了"其他 harness 只是我人工扫过一遍，那不是机制"**——这一轮就是把那句话兑现。

机制的形状很简单，正因为简单才可靠：**在跑任何 harness 之前，把仓库里每一个被跟踪文件哈希一遍；
跑完之后再哈希一遍；不一样就是有问题。**

```sh
fingerprint() { # 被跟踪文件的哈希
  ( cd "$ROOT"
    git ls-files -z | tr '\0' '\n' | LC_ALL=C sort | while IFS= read -r p; do
      if [ -f "$p" ] || [ -L "$p" ]; then
        printf '%s  %s\n' "$(sha256sum -- "$p" | cut -d' ' -f1)" "$p"
      else
        printf '%s  %s\n' MISSING "$p"     # sha256sum 对不存在的路径只往 stderr 说话然后继续
      fi
    done )
}
```

三个细节是设计过的，不是顺手写的：

* **`MISSING` 是印出来的，不是跳过的。** `sha256sum` 碰到不存在的路径会往 stderr 抱怨一句然后继续，
  于是"文件被删了"和"文件没变"在输出上长得一模一样。一个 harness `rm` 掉一个被跟踪文件必须能被看见。
* **未跟踪文件单独一张表。** 哈希表抓"内容变了"，未跟踪表抓"多了一个文件"。后者不是假想的：
  这个仓库曾经因为一句反引号在仓库根目录留下过一个叫 `file` 的空文件（`96` 记着那件事）。
* **基线是"跑之前的工作树"，不是 index。** 这个脚本经常在一个**本来就有未提交改动**的树上跑；
  它要抓的是**家族改了什么**，不是作者还没提交什么。这一条有自己的场景（§5），因为一个把
  "树是脏的"报成"树被改了"的检查会天天喊狼来了。

并且**两种"取不到指纹"都是拒绝**（`exit 2`）：根目录不是 git 仓库；以及**取回来是 0 个文件**
（index 是空的，或者路径读不出来）。第二种值得单独说：**空指纹和空指纹是相等的**，所以它会
把每一次运行都报成"干净"——那就是"不可能失败的检查"，只不过比 harness 里的那些高一层。

`--no-fingerprint` 是给"我就是要跑一下、我知道我在哪"的人留的，但它**在汇总里印出来自己没做这件事**：

```
== the tree check was SKIPPED (--no-fingerprint): this run says nothing about whether the family edited the repository
```

## 4. 三种"不绿"，和一条什么都不做的过滤器

一个 harness 印不出数字，和它的数字是 0，是两件不同的事。所以：

| 行 | 什么时候 | 为什么不能算绿 |
|---|---|---|
| `FAIL  <name>  pass=… fail=… rc=…` | 它自己说 fail≠0 或 rc≠0 | —— |
| `NOSUMMARY  <name>  rc=…` | **它一行 `pass=` 都没印** | 崩溃、早退、印到别处去了——三种都长得像 `rc=0` |
| `TIMEOUT  <name>  rc=124` | `timeout -k 5 SECS` 杀的 | **这是仪器没跑完，不是被测对象失败**——两者要分开说 |
| `verdict: THE TREE CHANGED` | 指纹变了 | 见 §3 |

还有一条**拒绝**：`--only` 匹配不到任何 harness 时 **`exit 2`**，理由是

```
A run over nothing reports zero failures, which is the check that cannot fail.
```

——一个悄悄选空了集合的过滤器，和"这一套全都通过了"在输出上是一样的。

## 5. 离线验证：85 检查，四个变异各自让它红

夹具是**一个真的 git 仓库（在 /tmp）**加上八个极小的 harness。指向真仓库会让每个结论变成
"这台笔记本怎么样"，更糟的是**树检查的场景必须真的破坏真树才观测得到**——那就是缺陷本身。
（`128` §9c 在同一个理由下做过同样的选择：它的"哈希检查能不能红"是在一个 **scratch 树**上演示的。）

| 场景 | 期望 |
|---|---|
| 两个绿 harness | `exit 0`；**总数是 7 + 11 = 18**（算术，不是这里打的字） |
| 跑之前树就是脏的 | **`exit 0`**，报 `the repository is unchanged`——基线是"跑之前的样子" |
| 一个红的 | `exit 1`；它自己的 `FAIL` 行被顶到台面上（操作者不用去开文件）；`5 checks, 2 failing` |
| 一个**什么都不印**的 | `NOSUMMARY`，**不是** `PASS` |
| 一个超出 `--timeout` 的 | `TIMEOUT`，指名 `timeout(1)` |
| `--only` 匹配不到 | `exit 2`，并且说清楚"那就是不可能失败的检查" |
| **一个往被跟踪文件里追加、还印 `pass=9 fail=0`、`exit 0` 的** | **`exit 3`**，点名 `tracked.txt`，汇总**不**说 unchanged，而且**那一行仍然写着 1 green**——行为全绿与仓库被改**故意**不一致，树说了算 |
| 一个**新建**文件的 | `exit 3`，报成"仓库里多了一个文件"，不是"内容变了" |
| 一个**删掉**被跟踪文件的 | `exit 3`，报成 `MISSING` |
| 一个又绿又无害的（对照组） | 树保持干净——所以红的树检查**不能**用"这次运行写了点什么"来解释 |
| 加了 `--no-fingerprint` 的同一个写入 harness | `exit 0`（`1` 都不是），**但**汇总印出"检查没做" |
| 一个不是 git 仓库的根 | `exit 2`，理由是**它取不到指纹**，不是"仓库坏了" |
| 一个 git 仓库但 **index 是空的** | `exit 2`，理由是**指纹取回来是 0 个文件**，且**不**去怪那个仓库（它就是 git 仓库） |
| `--quiet` | 每个 harness 一行 + 汇总（**判定行不该被静音**——第一版照抄了 heat chain 的 `say`，在 quiet 下把 PASS 行整个吞掉了） |

**变异测试**（一个不能失败的 harness 什么也证明不了）：

| 变异 | 结果 |
|---|---|
| 把 `FP_AFTER=$(fingerprint)` 换成 `FP_AFTER="$FP_BEFORE"` | 红：**一个改了树的 harness 被报成全绿** |
| 把"没有摘要"那一支改成**默认 0** | 红：**什么都不说的 harness 被记成 pass**，旁边还写着 `0 checks`——那个 0 是因为**没有东西可数** |
| 整块删掉"不是 git 仓库"的拒绝 | **仍然 `exit 2`**，但改由 **0 个文件那个守卫**拒绝——**保护不是一句话**，删掉一句会落到另一句上，而不是落到沉默上 |
| 删掉未跟踪文件的比对 | 红：**仓库里多出来的文件不再被看见** |

第三个变异的做法本身也是修出来的：第一版只替换了那块里**第一行 `echo`**，把 `exit 2` 留在原处，
于是变异体因为一个**和这次变异无关**的理由拒绝，那个场景什么也没证明。（`mutate()` 里那条
"这个 sed 必须真的改到 shipped 脚本的一行"的守卫抓不出来这种——它确实改到了。是**断言**抓出来的。）

顺带在这一轮里修掉的：家族总数里那个 `19` 一开始也是**手打的**（断言里写死 `^19 harness(es)`）——
那是这一轮要消灭的缺陷本身。现在它是**在 harness 里数目录得到的**，并且另有一条断言
"这个文件自己也在那份名单里，而 runner 不在"（runner 的 glob 是 `zl1-*selftest.sh`，
它的名字 `zl1-selftest-family.sh` **不匹配**——一个匹配到自己 glob 的 runner 会跑自己）。

## 6. 这一轮**不**证明什么

* **不证明这些 harness 覆盖得够。** 家族 runner 只报告"每个 harness 说了什么"和"树有没有被改"，
  它对**覆盖面**没有任何意见——那是每个 harness 自己的事。
* **不证明"树没变"就万事大吉。** 它只看得见**被跟踪的文件**（加上未跟踪的新文件）。一个 harness
  在仓库外面（比如 `/tmp`、或者被 `.gitignore` 排除的 `tmp-*/`）写东西，这个检查**看不见**，
  而且大部分情况下那是正当的。
* **不证明 3 分钟是可接受的。** 这一族现在跑 2m45s，而 `--only` / `--list` 是给它留的出口；
  真到嫌慢的时候该做的是**把家族拆开跑**，不是把这个检查去掉。
* **不证明它能代替 `128` §9c。** 那一条盯着**一个具体的文件**并且在**每一次**跑那个 harness 时生效；
  这一条盯着整个仓库但只在**跑整个家族**时生效。两条都在，因为它们挡的不是同一个时刻。
* **不证明设备侧的任何事。** 整轮没有一次 ssh。
