## The one remaining problem

The device's outbound packets stop reaching the driver shortly after each boot, while every
other indicator stays healthy. Measured across one boot
([`30`](30-outbound-drops-before-the-queue.md)):

```
uptime 42.50  RX 1160/19  TX 1418/19  qlen=0 throttle=0  host-ping OK
uptime 61.22  RX 1412/22  TX 1712/22  qlen=0 throttle=0  host-ping FAIL
```

3 packets out for ~7 ping attempts in 18.7 s, with `tx_dropped=0`, `tx_errors=0`, the
interface UP, both addresses present, the routes present, and the ARP entry for the host
complete. Packets that vanish without moving any netdev counter are dropped *before* the
device queue — netfilter, or a policy-routing rule.

Everything points at Android's netd, which shares the network namespace
(`lxc.namespace.keep = net user`) and comes up at about the moment the link dies. The
correlation I dismissed too quickly earlier — no `/data/system.img`, no container, link
fine for 8+ minutes — is the strongest evidence there is.

## Next, in order

1. **Read the netfilter state on the device.** `netwatch` now snapshots `ip rule show`,
   `ip route show table all`, `ip route get 192.168.2.100` and the iptables counters at
   uptime 45 s, at the first stall, and at 120 s — the 45/120 pair brackets the break.
   `ip route get` alone separates "routing is fine" from "policy routing took them", and the
   iptables counters separate "a rule exists" from "a rule is eating packets".
   Needs one power-cycle into TWRP to redeploy the watchdog, then a read afterwards.
2. **Or the A/B, which needs no new instrumentation:** `container-ab-test.sh --yes` in
   TWRP hides `/data/system.img` so the container cannot start, measures, and stops. If the
   link holds for ten minutes, the container is confirmed. Reversible by renaming back.
3. With the cause pinned, the fix is likely in the UT-side or Android-side network
   configuration rather than in any image this repo builds.
4. Then the plan items still open: Stage 2.4 (three consecutive cold boots) and 2.5
   (rollback drill). Both have scripts; neither has been run.
