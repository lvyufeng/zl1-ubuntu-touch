## 2. 缺口：这条链的证据是"installer 返回 0"

`118` 把发烫的修复做成了一条链，理由是那是一个**许可链**：每一步的下游都依赖上一步，而一次 boot 不是免费的。
它做得很好的一件事是**顺序**，和每一步做完**从设备上重读**下一步的前置条件。

但它**没有测效果**。链跑完之后，操作者能看到的是：

* 两个 installer 各自的 read-back 打印了 `governors: interactive interactive interactive interactive`、
  `keeper: gone`；
* 于是这次 boot 的结论是"两个发烫的修复都装上了"。

这正是 `124` 那条规矩要防的东西，只是**防漏了它自己**：

> **一个 installer 退出 0，和一个旋钮真的动了，是两个不同的事实。**

链上每一环都在用这条规矩（netwatch 要 `--activate` 并证明是**正在跑**的那个 build；keeper 要一份
`proof-obtained` 的整行许可），唯独**这条链存在的那件事**——"手机是不是真的不烫了"——没有仪器。

而且仪器**早就写好了**：`device/zl1-thermal.sh` 的 `--ab` 模式就是干这个的，它的头里逐字写着

```
#   ssh root@10.15.19.82 'sh /tmp/zl1-thermal.sh --ab --hold 30' &
```

——**就是给宿主这么驱动的，而被驱动的那一方从来没有调用过它。** 所以这一轮不是造仪器，是接线。

## 3. 接线：它测什么、印什么、拒绝说什么

形状：链在第 04 步（地址所有权证明）判完、**在第一个修复之前**把 A/B 起在后台（`&` + `wait`，
和 settle 同一个理由：前后的前台命令会把 trap 推迟，`108`），两个修复跑在它中间的那个 hold 里。
于是**窗口 A = 换完 netwatch、还没动发烫的状态**，这正是两个具名原因需要的基线。

新参数（都有默认值，`ZL1_AB_*` 环境变量可覆盖）：

| 参数 | 默认 | 意思 |
|---|---|---|
| `--ab-hold SECS` | 120 | hold 的长度。两个修复跑在这段时间里 |
| `--ab-window SECS` | 30 | 每个采样窗口的长度（仪器要两个） |
| `--no-ab` | 关 | **完全不测**。是选择，不是读数，而且会印出来，绝不静默 |

状态机有六种，**每一种都在 `INDEX.txt` 里有一行**（第一版在 skipped/unusable 时提前 return，
于是**恰恰在最需要知道"为什么没有读数"的运行里**，那一行不存在）：

| 状态 | 什么时候 | 印什么 |
|---|---|---|
| `skipped` | `--no-ab` | `This is a CHOICE, not a reading` |
| `unusable` | 仪器在本机不存在，或 scp 失败 | 说明**原因**，并说效果**未测** |
| `failed` | ssh 返回非 0 | 带着**仪器自己的返回码** |
| `empty` | 返回 0，**但输出里没有差值段** | `Return 0 is not a measurement` |
| `done` + 对齐 | 正常 | 两段差值 + 污染说明 |
| `done` + 未对齐 | 工作超出了 hold | `NOT ALIGNED ... 当作被污染` |

**对齐算术在宿主时钟上做**，这是关键的一小段：设备时钟是错的、它的时间戳不可排序（`87`），
所以两边都用这台笔记本的钟：窗口 A 从 ssh 启动算起（`T0`），工作结束在最后一个修复返回时（`WORK_T`），
窗口 B 从 `T0 + 窗口A + hold` 开始。`margin = B开始 - 工作结束`，`margin < 0` 就是
**窗口 B 里还含着工作的一部分**——那时链印的是

```
   NOT ALIGNED: window B began 3s BEFORE the work finished, so its window still contains
   part of the work rather than only its result. Treat the deltas as contaminated and say so
   if you quote them.
```

而不是把一个温度差值当作两个修复的结果。没有这一条，一个"测量"会在**它测的东西还在跑**的时候印出数字。

最后，这段文字的结尾是**明确的否定**，不是留给读者推断的：

```
That end state is the MECHANISM, and it is what this chain can settle. Whether the phone runs
cooler is what 06b-heat-ab.txt is for ... this chain prints no verdict on the heat itself, in
either direction.
```

（harness 里有一条断言就盯这句话：早先写成 `notwant 'the heat is fixed'`，那是个**空真的**检查——
一个什么都不印的链也能过；现在是正面断言那一句 + `notwant 'verdict: heat-fixed'`。）

## 4. 离线验证：107 → 159，变异 7 → 10

第 5b 节把六种状态各驱动一遍（**每种都有自己的归档目录**：共用一个目录会让上一个场景的 `INDEX.txt`
满足下一个场景的断言，这是兄弟 harness 记过的"残留状态"缺陷）：

| 场景 | 期望 |
|---|---|
| 正常 + 对齐 | `06b-heat-ab 0`；两段差值都印出来；`ALIGNED`；操作者也看到同样的两段 |
| `--no-ab` | `skip`，**不是** 0；`zl1-thermal.sh` 既没被推也没被跑 |
| 本机没有仪器 | `unusable`，**指名那个路径**；链照常跑完（缺仪器不是跳过发烫修复的理由） |
| 返回 0 但**什么都没印** | `empty`，**不是** 0；理由说"空"，不是说返回码 |
| 仪器返回 7 | `7`；链**不中止**（一次测不到的效果不该让链半途而废） |
| 工作超出 hold | `NOT ALIGNED`，归档和读数里都有 |

**变异测试**（一个不能失败的 harness 什么也证明不了）。新增三个，每个都改了**被发出的脚本**的一行、
并且先断言"变异体走到了那些步骤"：

| 变异 | 结果 |
|---|---|
| `abnocontent`：把"输出里必须有差值段"那一支删掉 | 红：**一次空测量被记成成功**（`06b-heat-ab 0`），而且没有人被告知它是空的 |
| `abnoalign`：把 `if [ "$margin" -ge 0 ]` 改成 `if true` | 红：**一个仍然含工作的窗口被报成 ALIGNED**，操作者也收不到警告 |
| `abnoverdict`：只把"不给结论"那段删掉 | 红：差值照印，**"它不是什么"没了**（数在、话没了，正是这条树最怕的那个形状） |

前两个变异块第一版的 `sed` 缩进写成了 4 个空格以外的量，**一行都没匹配上**——
`mutate()` 的"必须改到被发出脚本的一行"守卫把它们抓了出来；第三个则是因为原来的断言是
**只剩否定**（`notwant`），加成了正面断言。

## 5. 顺带发现的第二件事：这个 harness 正在吃掉它自己测的仪器

写 A/B 夹具的时候，`git status` 里有一条从上一轮就一直在的东西：

```
 M scripts/device/zl1-thermal.sh
```

`git diff --stat` 说的是：

```
 scripts/device/zl1-thermal.sh | 410 +-----------------------------------------
 1 file changed, 1 insertion(+), 409 deletions(-)
```

**整台仪器 —— 409 行、21047 字节，这个项目唯一的热量仪器 —— 被换成了它自己夹具的一行注释。**

原因在三行代码里，而它们**每一行单独看都是合理的**：

```sh
# 第 65 行：假仓库的 scripts/device 是整个目录的符号链接，指向真目录
ln -s "$(cd "$HERE/../device" && pwd)" "$W/fake-repo/scripts/device"
...
# 第 114 行：穿过那个链接 mkdir -p —— 静默成功（链接已经指向一个存在的目录）
mkdir -p "$W/fake-repo/scripts/device"
# 第 116 行：往里面"放夹具"
printf '# the real instrument is scp-ed; this only has to exist and be readable\n' \
  > "$W/fake-repo/scripts/device/zl1-thermal.sh"
```

而第 65 行上面那段注释**写着相反的话**："a symlink keeps 'it pushed the REAL proof' true"。
链接的用途（让链推**真的**证明脚本，而不是一个替身）是对的；**同一个链接也让仪器可以被写掉**，
因为一个目录链接**分不清**"链真的要推的文件"和"这个 harness 有替身的文件"。

两点值得单独记：

* **没有任何一条检查能看到它。** 那 151 项断言全绿——它们断言的是**行为**，而这是一个关于
  **仓库**的事实。上一轮我就是这样从它上面走过去一次的：`git status` 一直在列它，我读的是
  `git diff` 里"我预期会改"的那几个文件。
* **同一个场景还把真文件 `mv` 走了再 `mv` 回来**（"仪器不在本机"那一支）：测试期间仓库里那个文件
  短暂地不存在。同样是那个链接的后果。

修法是三件，而且缺一条都不够：

1. **每个文件单独链接**（`DEV_FAKE`）：除 `zl1-thermal.sh` 之外的每个设备脚本都指向真文件，
   **证明脚本仍然是真文件**（所以"它推的是真的那个"仍然是可测的），而仪器的替身是
   **这个 harness 自己树里的普通文件**。
2. **写操作走 `wrote()` 守卫**：目标**是符号链接就拒绝**（`exit 2`）。这是机制，不是约定——
   "上面的循环跳过了那一个名字"这种保证必须在每次编辑时重读，而这个守卫在写的那一刻生效。
3. **整轮前后对真文件取哈希**，并且新加的第 9c 节把三件事都断言出来：真文件逐字节不变、
   替身不是链接、证明是同目录里指向真文件的链接。
   （这三条检查各自的"能不能红"也测了：`wrote()` 被**直接**在一个符号链接上调用一次，必须在**子 shell** 里
   拒绝——一个已经不再拒绝的守卫应该记成一条失败，而不是把整个 harness 带走；
   而哈希那条的"能不能红"用一个 **scratch 树**演示——真的在一个 scratch 目录上重现那两行，
   证明穿过目录链接的写**确实**会改变被测量的文件。）

顺带把另一条"声称"变成了测量：链推的证明脚本现在用 `cmp` 和仓库里的文件逐字节比对
（原来只断言了**名字**，一个同名的替身同样能过）。

**这一节是这一轮的第三层**：`126` 是"一个文件的 shape 被当成了它回答的东西"，`127` 是
"一个前置条件只被问了一半"，而这里是**一个测试在改动它测的东西，而所有断言都在看别处**。

## 6. 这一轮**不**证明什么

* **不证明手机不烫了。** A/B **从来没有在设备上跑过**：这一轮把它接上了，而它一次都没有测到过一个
  真实的温度。链自己的文字就是这么写的——它给的是**机构**，不是效果，**两个方向都不给结论**。
* **不证明 A/B 的形状是对的。** harness 里那台"仪器"的输出是**从这台机器上一次真实运行里抄下来的**
  （`--ab --hold 3`），所以链解析的形状是仪器**真的会印**的形状；但链从来没有和**设备上跑的**那台
  仪器面对面过。
* **不证明 hold 的默认值 120 秒是对的。** 它只是"比两个修复需要的长"这个判断；真正的数字要等第一次实跑。
* **不证明第 9c 节能覆盖别的 harness。** 扫过一遍：这一族里只有 `zl1-heat-fix-chain-selftest.sh`
  把**真仓库目录**链接进假仓库又往里写；其余的假仓库是**真目录**。但这是一次**人工扫**，不是一条机制。
* **不证明宿主现在是齐备的。** `127` 加的那个前置检查报的是"这台笔记本现在怎么样"，而那是一次读数。
* **不证明设备侧的任何事。** 整轮没有一次 ssh。

## 7. 设备状态与复现

整轮没有动设备：没有写任何分区或 boot，没有跑 QDL/QFIL，没有重启。设备仍在 **Qualcomm EDL**
（`05c6:9008`，port 3-3，无序列号）。识别目标一律按序列号 **`33e80afe`**；总线上另一台小米
**`4a2fe00b`** 必须忽略。恢复仍然只能靠**物理长按电源 10–20 秒**。

```sh
# 全部在宿主机上，不碰设备。
bash scripts/host/zl1-heat-fix-chain-selftest.sh                  # 159 项

# 这一轮最该被记住的那条读数：这台 harness 跑完之后，仓库里的仪器必须一个字节都没变。
sha256sum scripts/device/zl1-thermal.sh                           # 跑 harness 前后各一次，应当相同
git diff --stat scripts/device/zl1-thermal.sh                     # 必须是空的

# 仪器自己的 --ab 形状（在这台笔记本上跑，不碰设备）：
bash scripts/device/zl1-thermal.sh --ab --seconds 3 --hold 3

# 9c 那一节里"哈希检查能不能红"的演示就在 harness 里（scratch 树那一支），而且是**故意**不在
# 仓库上做的：真要在真文件上演示那个缺陷，就等于把缺陷再做一遍。同一条理由也是那个守卫检查必须
# 指向 $W 内部的链接而不是 scripts/device/ 里的那个——一个"不再拒绝"的守卫只应该能弄坏 $W。
# 想看那条演示本身，直接跑它并读 9c 的六行：
bash scripts/host/zl1-heat-fix-chain-selftest.sh | sed -n '/9c\./,$p'
```
