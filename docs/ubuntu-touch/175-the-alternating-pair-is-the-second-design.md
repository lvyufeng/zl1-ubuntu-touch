## 1. 一句话结论

| 问题 | 答案 |
|---|---|
| 这一轮买到了什么？ | **第二种设计，和一个必须写下来的发现：交替顺序是承重的。**`--pairs N` 跑 N 对（fix 窗口、pinned 窗口），读数是每对之差 `B - A` 的**均值**，误差棒是这些差的**散布**——于是"要求噪声为零"变成了"知道噪声是多少"，而**判词可以是不确定的**（`inconclusive`），那是三窗口设计说不出来的一个答案。 |
| 它为什么不漂不行？ | 因为三窗口的毒在**要求**里：它要窗口 A 是一个**状态**（pre-hold 保证 A 之前不动，wait 保证 C 之前回来），而 docs 174 把这条要求变成了算术——默认值下**一个 10 秒区间只允许 0.012 °C**，比仪器自己的 0.1 °C 步进还小。**这台手机永远过不了它，所以设计必须停止要求。** |
| 交替顺序为什么是承重的？ | **因为同一对里，后取的那个窗口天生比先取的那个晚一个窗口。**若每一对的顺序相同（都是 fix 然后 pinned），pinned 窗口永远晚一个窗口，于是**每一条差里都带着同符号的一个窗口的漂移**，均值就是效应**加上**那个漂移。让顺序交替（第 1 对 fix→pinned，第 2 对 pinned→fix），两半在时间上的**平均位置相同**，漂移在**全部差的均值**里抵消，而不只是在"配对之间"抵消。 |
| 这件事有多大？ | 离线可看，而且**同一台假手机**：效应 2.0 °C、漂移 1.0 °C/窗口。交替顺序读 **2.00**，固定顺序读 **3.00**（差的就是那一个窗口的漂移）。而运行自己会把这件事**印出来**：固定顺序下 balance 是 **1.00 个窗口**，它自己量到的漂移是 **1.00 °C/窗口**，两个数相乘正好是那个 1.00 °C 的偏差。 |
| 误差棒从哪来？ | **从数据**：`se = sd(d_i) / sqrt(N)`，而 `sd` 用平方和一遍算出来。判词是**区间对门槛**：`mean - 2·se` 超过 0.2 °C 就是 `cost-measured`，`mean + 2·se` 不到 0.2 °C 就是 `no-detectable-cost`，区间**跨过**它就是 `inconclusive`（退出 1）——并且它会说**再要多少对**，以及那个数**是否已经超出 `--pairs` 自己允许的 30**。 |
| 主 zone 怎么选？ | **在第一个窗口里声明**（A.1 里最热的 tsens zone，在任何干预之前），然后**再也不动**。理由是 docs 172 那个形状：**N 个均值里最大的那个，即使什么都没发生，也会高出两倍标准误**——所以"事后挑最大的"必须被结构挡住，而不是被自律挡住。选不出来的时候它**说出来**（`PRE_REG=0` + 警告行），不挑一个漂亮的。 |
| drift 怎么处理？ | 两种，都印出来：**控制**（fix 窗口自己每窗口走了多少 °C，用**运行记录的**位置算速率，不是用设计的算术重算）和**平衡**（两半在时间上的平均位置、失衡多少个窗口、以及这个失衡在它自己量到的漂移下值多少 °C）。 |
| 它做不到什么？ | **lag**。zone 是跟着功率走的，中间隔着 SoC 的热时间常数（仍然没量过，docs 173 §8），所以窗口若和那个常数同量级，它会**低估**效应。别的都在这两页里说清楚了，这一条是这一页不能解决的。 |
| 离线怎么被证明的？ | harness **242 → 321 条全绿**：9 个新场景、3 个新变异（m16/m17/m18）、9 条静态断言。其中最重要的一条是**变异必须被它自己的账目抓住**：固定顺序（m16）之后，均值变 3.00、balance 变 1.00 个窗口、那个失衡被折算成 1.00 °C。 |
| 上设备了吗？ | **没有。**321 条检查全是对着假设备跑的。 |
| 设备现在怎么样？ | **这一轮没有读它**（见"状态"一段）。 |

## 2. 为什么需要第二个设计（重复一遍，因为这是它的全部理由）

docs 174 把三窗口设计的要求**算了出来**：

```
一个 10 秒区间允许 0.5 × 10 / 415 = 0.012 °C
```

比仪器自己的 **0.1 °C 步进**还小。也就是说：**任何在 10 秒里动了一格的手机都过不了 pre-hold**，
包括 docs 173 那一趟（它 10 秒动 0.4 °C）。而那趟手机在整趟运行里移动了约 **4 °C**，
要定价的效应约 **2 °C**（③ 量出来是 5.5 °C，②按形状是 2 °C 量级）。

三窗口的毒不在门槛，在**结构**：它需要 A 和 C 是**同一个状态**，而"同一个状态"这件事在这台手机
上的代价就是"整趟不许动"。**所以改的不是尺，是设计**——把漂移消掉，而不是要求它不存在。

---

## 3. 形状：`A B A B …`，而且**每对内部的顺序交替**

N 对，每对两个窗口（fix `interactive`、pinned `performance`），每个写入都由**读回**证明，
每次写入后 settle。读数：

```
d_i = B_i - A_i            （同一对里的 pinned 窗口减 fix 窗口）
读数 = mean(d_i)  ，误差棒 = sd(d_i) / sqrt(N)
```

**pre-hold 和 wait 在这个设计里被跳过**，这不是省时间，是它们的**用途**消失了：它们的存在是为了让
窗口 A 成为一个**状态**，而配对之差比较的是**相隔一个窗口**的两个窗口，不是相隔一整趟的两个读数。

而顺序是承重的，理由只需要一行算术：

| 顺序 | fix 窗口的位置 | pinned 窗口的位置 | 均值差 |
|---|---|---|---|
| 每对都是 fix→pinned（N=4） | 1, 3, 5, 7（均值 **4.00**） | 2, 4, 6, 8（均值 **5.00**） | **1.00 个窗口** |
| **交替** fix→pinned, pinned→fix | 1, 4, 5, 8（均值 **4.50**） | 2, 3, 6, 7（均值 **4.50**） | **0.00** |

pinned 窗口在每一对里都比它自己的 fix 窗口**晚一个窗口**，所以若顺序固定，那个偏差**每一对都同号**，
在均值里**不相消**。交替让两半在时间上的平均位置相同，漂移才真的从均值里掉出去。

**而且这个数是运行时算出来的，不是设计里写死的**：运行把每个窗口**取用的顺序**写进 `$TMP/order`，
balance 和漂移速率都从那个文件读——所以一个取错顺序的运行报告的是**它自己造成的失衡**，
而不是它的算术以为的失衡。离线把这件事变成可看的：m16 把顺序固定回去之后，
balance 行自己印出 **1.00 个窗口**。

## 4. fixture 里的算式（这一页的每个数都能手算）

假手机的表是 `zone i = 42.0 + i·0.5 + 漂移·(窗口号 - 1) + 干预的余热`。取 **效应 2.0 °C、
漂移 1.0 °C/窗口**、4 条 zone，交替顺序下 8 个窗口的**最热 zone** 是：

| 窗口 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 角色 | **A.1** | B.1 | B.2 | **A.2** | **A.3** | B.3 | B.4 | **A.4** |
| 温度 | 42.0 | 45.0 | 46.0 | 45.0 | 46.0 | 49.0 | 50.0 | 49.0 |
| 每对的 `d_i` | — | **+3.0** | **+1.0** | — | — | **+3.0** | **+1.0** | — |

* `mean = (3 + 1 + 3 + 1) / 4 = **2.00**` ——**正好是效应**，漂移在均值里抵消了；
* `sd = sqrt(4/3) = 1.155`，`se = 1.155/2 = **0.58**`，区间 `[0.84, 3.16]`，下界仍在 0.2 °C 之上 → `cost-measured`；
* fix 窗口的位置是 1、4、5、8 → 平均 **4.50**，pinned 是 2、3、6、7 → **4.50**，失衡 **0.00**；
* 漂移速率从**记录的位置**算：`(45-42)/3`、`(46-45)/1`、`(49-46)/3` 全是 **1.00 °C/窗口**。

**固定顺序（m16）下同一台假手机**：窗口是 42, 45, 46, 49, 48, 51, 50, 53，
`d_i = 3, 3, 3, 3` → `mean = **3.00**`、`sd = 0`、`se = 0.00`、区间 `[3.00, 3.00]`；
fix 位置 1、3、5、7（4.00），pinned 2、4、6、8（5.00）→ 失衡 **1.00 个窗口**，
它自己量到的漂移 **1.00 °C/窗口**，于是"**worth about 1.00 C of the reading**"——
**偏差 1.00 °C，正好是 3.00 与 2.00 之差**。这台仪器把自己的缺陷定了价。

另外两个场景的算术同样是手算的：**效应 0、漂移 0.1** → `d_i = ±0.1` → `mean 0.00`、`se 0.06`、
区间 `[-0.12, 0.12]` → `no-detectable-cost`（脚本反对它自己）。**效应 0.5、漂移 1.0** →
`d_i = 1.5, -0.5, 1.5, -0.5` → `mean 0.50`、`se 0.58`、区间 `[-0.66, 1.66]` → `inconclusive`，
并且它算出**再要约 60 对**——**超出 `--pairs` 自己允许的 30**，所以它补一句"这不是更多对能解决的"。

## 5. 判词、控制、以及它做不到的那一件事

| | 这一页给出什么 |
|---|---|
| 判词 | 三种，都是**区间对一个** 0.2 °C 的门：`cost-measured`（退出 0）、`no-detectable-cost`（退出 0，**脚本反对它自己**）、`inconclusive`（退出 1）。第三种是新的，说的是**数据**而不是 governor。 |
| 主 zone | **第一个窗口里声明**，之后不动。选不出来就印警告并把它当成"事后挑的"那种最弱的证据。 |
| 控制一 | **漂移速率**：fix 窗口自己每窗口走了多少 °C，按**记录的位置**算。 |
| 控制二 | **balance**：两半的平均位置、失衡多少窗口、在量到的漂移下值多少 °C。 |
| 累计 | 每个窗口的写入都读回证明；`WROTE` 在写之前就置位，undo 读回成功才清零；一个 EXIT trap 同时做 restore 和 cleanup。 |
| **做不到** | **lag**：窗口若与 SoC 的热时间常数同量级，效应被**低估**——偏在"fix 看起来更便宜"那一侧，不是更贵。 |

**`--pairs` 自己的范围是 3..30**：至少三对才谈得上"散布是噪声的估计"，至多三十对才是"这趟运行
能按它的墙钟安排"。非数字的 `--pairs` 在**任何算术之前**就被 `case` 拦下（否则 `$(( ))` 会在
消息之前让 shell 中止）。窗口长度的默认值是 30 秒、settle 5 秒——六对约十分钟，运行会印出实际花的。

## 6. 离线怎么被证明的：321 条检查，9 个场景，3 个变异，9 条静态断言

| 场景 | 造出来的手机 | 断言的是 |
|---|---|---|
| `pairs-cost` | 效应 2.0、漂移 1.0（**正是 §3d 拒绝的那台**） | 判词 `cost-measured`，**读数是 2.00 而不是 3.00**，`se 0.58`、区间 `[0.84, 3.16]`，主 zone 被标出，balance 是 `4.50 / 4.50`、失衡 0.00，控制是 `+1.00 C per window`，**pre-hold 没有跑**，8 次仪器调用，设备按字节复原 |
| `pairs-nocost` | 效应 0、漂移 0.1 | `no-detectable-cost`（退出 0），一个价钱都没印 |
| `pairs-inconclusive` | 效应 0.5、漂移 1.0 | `inconclusive`（退出 1），区间两端都印，**"再要约 60 对"**以及"超出 30" |
| `pairs-quiet` | 仪器什么都不答 | 没有读数就没有判词（退出 1），核仍然被放回，设备按字节复原 |
| `pairs-interrupt` | 在**某一对**的 pinned 窗口里被杀 | 退出非 0、`[trap]` 说话、核回到 `interactive`——一个 trap 覆盖两个设计 |
| `pairs-status` | `--status --pairs 4` | 退出 0、**一个字节都没写**、8 个窗口 4 对、说明顺序交替、pre-hold 与 wait 不适用、没有判词 |
| `--pairs 2` / `--pairs 99` / `--pairs abc` | 三个参数错误 | 退出 2、说出 3..30 的范围、**没有读窗口、没有写、核没动** |

| 变异 | 把什么放回去 | 它必须被看见 |
|---|---|---|
| m16 | 每一对的顺序固定（不再交替） | 读数变 **3.00**、balance 变 **1.00 个窗口**、那个失衡被折算成 **1.00 °C**——**缺陷被它自己的账目定价** |
| m17 | 判词不再用误差棒（`lo = hi = mean`） | 区间跨过门槛的那台手机就**印出价钱**了——"误差棒是全部意义"这句话变成可执行的 |
| m18 | 主 zone 在事后挑选（预注册被删） | 警告行印出一个**没发生**的失败，而判词照印——数字是从数据里挑的，没有任何东西说这件事 |

**静态断言钉在源头**（注释剥掉之后）：三个 `if [ "$PAIRS" -gt 0 ]` 守卫里有一个是 pre-hold 的
**跳过**（断言数的是守卫的个数）；交替顺序那一行；`sqrt(var / m)` 那一行；主 zone 来自 `win.A.$zl1_i`；
`PRE_REG=0` 那一行；balance 从 `$TMP/order` 读；顺序文件由运行**自己写**；
判词是 `lo >= res` 而不是 `m >= res`；`inconclusive` 这个输出存在。

**这一轮没有新增 fixture 能力**（上一轮的 `FP_SAMPLE_COST` 在这一页没用上），
但用足了上一轮给的那一个：**一台会漂移的假手机**。没有漂移，"配对抵消漂移"就无从检验，
而 m16 也正是靠漂移才看得见——**一个不漂的手机上，固定顺序和交替顺序给出同一个数**。

### 6.1 写这一页时发现的第三条：**一个计数在负载下不是一个计数**

把它放在这里，因为它和 docs 174 那两条是**同一个形状的第三次出现**，而且它是在**跑整套
family（42 个 harness、整棵树）的时候**露出来的，不是在单跑这一支的时候：

```
FAIL  the instrument ran 3 time(s): 4 pre-hold samples were expected      （no-plateau 场景）
```

**原因不是被测的东西**：docs 174 把两条 hold 的上界都放进了**时钟**，而 hold 循环的每一圈
花的是"它要的睡眠**加上**仪器自己"——所以 `--settle-start 4 --poll 1` 里放得下几次采样，
是 `4 / (1 + 仪器)`：**空闲的主机放得下 4 次，忙的主机只放得下 3 次**。代码没变、设置没变、
假手机也没变，而"采样几次"变成了一个**关于主机的数**。

修法是 `between`：那四处**挂在墙钟上的**计数改成断言一个**区间**，并且把**它看到的那个数
印在 PASS 行里**（"it took 3"）——留着的性质是"hold 比较了**不止一个**读数"和"运行没有失控"。
**而真正该被断言的那件事一直不是计数**：`notwant 'window A -- as installed'` 才是"一个窗口都没读"。
两处**本来就是确定的**计数保持精确：m14 的 5（它的上界数的是**睡眠**，是 fixture 自己的算术）和
`slow-samples` 的那一次采样（1 秒睡眠 + 2 秒仪器**就是**它被给的 3 秒）。

同一次跑里还有第二行红字：`zl1-governor-temp-ab.sh CHANGED during this run`——那是**我在这趟 family
还在跑的时候改了被测的脚本**。那是树指纹在**正常工作**（docs 136/159 的那条），不是缺陷；
能引用的绿是**改完之后重跑**的那一趟。

## 7. 这一页**没有**成立的东西

* **没有上过设备。**321 条检查全是对着假设备跑的。
* **②的价钱仍然没有。**三次运行、一次 `CONTAMINATED`、一次 artifact、一次拒绝；这一页没有让它更近。
* **lag 没量过。**热时间常数仍然是未知的，所以"窗口多长才够"这个问题没有被回答，
  而它的答案会决定这个设计**低估**多少。
* **窗口之间要不要更长的 settle、切换 governor 本身是否引入扰动、以及 `performance` 的
  余热在两个相连的 pinned 窗口之间是否叠加**（交替顺序在每两对之间会让同一个状态连占两个窗口），
  这三件**一件都没量过**。第三件是**已知的形状**：`B.1 B.2` 是连着的，`A.2 A.3` 也是。
* **`--pairs` 的默认值（30 秒窗口、5 秒 settle、最多 30 对）不是量出来的**，是从"
  window 要长过仪器自己的走 `/proc`（约 13 秒）"和"一趟要能按墙钟安排"推出来的。
* **60 对那个数不是观测**：它是这一趟自己的 `se` 外推的，而 `se` 是从 4 个点算的。
* **`inconclusive` 还没有在真机上出现过**，所以那条分支的措辞没有被真读数检查过。
* **设备时钟仍然是错的**（读 1970），这一页没有碰它。
* **跨重启的持久性仍然没量过。**

## 8. 阶段位置

| | docs 174 之后 | 这一页之后 |
|---|---|---|
| 设计 | 只有一个 A/B/C，而且它在这台手机上过不了 pre-hold | **两个**：A/B/C 是控制，`--pairs` 是能在这台手机上给数的那个 |
| 噪声 | 被**要求**为零（pre-hold 的尺度是"整趟位移"） | 被**测量**（配对之间的散布），而且**判词可以说"分不出来"** |
