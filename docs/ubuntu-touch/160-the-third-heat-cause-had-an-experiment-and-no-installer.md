# 160 — 第三因有实验，没有安装器

**日期**: 2026-09-25
**状态**: 本轮**没有碰设备**，而这一轮交付的是**散热第三因缺的那一半**：docs 121 命名了原因，docs 122
做了实验，docs 153 把机理从源码里读了出来——**而这三件加起来没有让这个修复活过一次重启**。

现在它有一个安装器，而安装器的**执照**就是这个实验自己的最后一行判词。

## 2. 缺口到底是什么形状

散热在这个工程里有**三个**被量出来、被命名过的原因，而只有两个可以被"装"：

| # | 原因 | 怎么修 | 状态 |
|---|---|---|---|
| 1 | v63 镜像里的调试 keeper，占 4 核里的 ~1 核 | `install-retire-debug-keeper.sh` | 有安装器，**从未在设备上跑过** |
| 2 | 镜像把四核钉在 `performance` | `install-cpufreq-governor.sh` | 有安装器，**从未在设备上跑过** |
| 3 | **SoC 不被允许进自己的低功耗梯子** | **这里** | 这一轮之前：**有实验，没有安装器** |

第三因和前两个不是一个形状：它不在文件系统里，它在**这次开机**里。每一个 zl1 的 cmdline 都以

```
lpm_levels.sleep_disabled=1
```

开头，而那是内建的 `lpm_levels` 驱动的一个**模块参数**（mode 0664），所以修复是一条运行时写
（docs 153 从发布的源码里把机理读了出来：闸门返回**层号 0**，而 `lpm_cpuidle_enter()` 把 0 号带进
`psci_enter_sleep()` 的 `if (!idx)` 分支——一句 bare `wfi()`。所以这个参数不是"选一个更浅的状态"，
是把梯子**从顶上拿掉**）。

而写**没有地方可存**：下一次开机那条 cmdline 又把它写成 1。**这不是疏忽，是那个实验的设计**——
`zl1-lpm-ladder-trial.sh --apply` 会写、会测、然后**按构造**放回去，因为它是**实验**，而"下一次开机"
就是它的撤销。一个把撤销做进设计的实验是好实验；一个**只有**实验的修复就是一个缺口。

所以这一轮的产物不是一个判定词，是一个**安装器**：

```
scripts/install-lpm-sleep-fix.sh --install --after-trial FILE
scripts/install-lpm-sleep-fix.sh --status
scripts/install-lpm-sleep-fix.sh --remove
```

## 3. 它的执照是**那个实验自己的最后一行**

**"那个文件是 0664"不是执照。**这是这个安装器存在的理由里最容易被跳过的一句：可写只说明
**写不会失败**，不说明**写会改变 SoC 的行为**。docs 121 把它说成假设，docs 122 就为此把 `REFUTED`
做成一个**可达**的结果——如果实验永远只会说"支持"，那它就不是实验。

所以这个安装器**不接受任何一句关于旋钮存在的话**。它要求实验自己的输出，而且要求其中的**最后一行**
恰好是下面这一个：

```
== verdict: supported-not-proven
```

这是五个结果里**唯一**同时说明"梯子确实被这个参数闸着"和"这一次跑得干净"的一个。另外四个**各自都
禁止安装**，而拒绝的时候脚本会**点名它读到的是哪一个**：

| 读到 | 为什么它禁止安装 |
|---|---|
| `refuted` | 参数为 1 时梯子**已经在用**了——那这个参数不是修复，装一个写它的 unit 等于装了一个空 |
| `not-supported` | 有 idle 机会而深状态仍然**一次都没进**——这个参数不管它看起来管的那个东西 |
| `inconclusive` | 计数器读不了，或者 CPU 从来没有 idle 过——**什么都没测到，而"我测不出来"不是"它有效"** |
| `confounded` | 一个混杂因素（keeper 在跑，或者那个状态被 disable 了）**自己就能产生这个符号** |

**是最后一行，不是任意一行。**一份归档输出里可以有不止一次运行（一次开机里 runbook 可以被调用
不止一次），而**从第一次匹配取执照**会让一次早先的 `SUPPORTED` 授权一次后来的 `REFUTED` 之后的安装。
**最近的一次读数是执照**，而脚本会印出它用的是哪一行。

### 为什么这一轮同时改了那个实验

因为上面这条要求在**同一轮**里暴露了实验的一个缺陷：**它的五个结果以前根本不是"行"，是散文**，
彼此靠退出码区分。对人够用，对任何**要据此做决定**的东西都不够——而从一个句子里抠许可证正是这个
仓库记过的缺陷（docs 114：一个子串闸门接受了一句**只是提到**那个词的话）。

所以实验的第 10 节现在在每个分支上印一整行 `== verdict: <name>`，散文留着，因为解释名字的是散文。

而把这一行写下去的时候，找到了**实验自己的一个真缺陷**：它的**第二个 `CONFOUNDED` 分支印着
"Exit 1." 而实际 `exit 0`**。脚本自己的 header 把退出 1 定义为"判定是 INCONCLUSIVE 或 CONFOUNDED"，
而这是它的两个 CONFOUNDED 分支之一；另一个（深状态**进过**、但有混杂因素）**一直**是 `exit 1`。
于是同一个词在两个分支上给出两个退出码。现在它是 `exit 1`，带注释记下这次的量法，并且在 harness 里
**有自己的场景**（`FAKE_KEEPER=1 FAKE_IDLE=shallow --apply --allow-keeper`：判定 `confounded` 且 `RC = 1`）。

**这就是"许可证没人能解析"的直接代价**：一个没人能解析的许可证，是一个没人会去核对的许可证，
而一个没人核对的退出码会从它自己的手册上漂走。

## 4. 第二个前提，也是那个**要命**的前提

实验是**按构造只属于一次开机**的：它跑的时候如果挂了，那次挂由一个重启界定。**这个安装器不是。**

它让梯子**从今往后每一次开机都生效**。而在这块板子上，内核 panic **默认会升级到 EDL**——
`download_mode` 是编进去的 1（docs 86），然后 bootloader 就**等一个人来按住电源键**。那件事是被
`install-no-edl-on-panic.sh --install` 关掉的，而 runbook 把它作为**第 02 步**跑，就在散热链之前一步。

所以这个安装器**拒绝**，除非每一个 `download_mode` 参数都读 0——理由和实验完全一样，只是代价更大：
从它装上那一刻起，"梯子开着的时候出了事"**必须**是一个重启，而不能是一台坐在 EDL 里等 10–20 秒长按的手机。

## 5. 它装了什么，以及**读回**为什么是规则

两个文件，都在 `/etc/systemd/system` 这条**可写**路径上（`/` 是只读镜像，而这里解析到 rw 的
`/etc/writable` 挂载——这个 port 已经加的 unit 就住在那里）：

| 文件 | 是什么 |
|---|---|
| `/etc/systemd/system/zl1-lpm-sleep-fix.sh` | applier（也能手工跑） |
| `/etc/systemd/system/zl1-lpm-sleep-fix.service` | `Type=oneshot`、`RemainAfterExit=yes`、`WantedBy=multi-user.target` |

applier 扫的是**每一个** `/sys/module/*/parameters/sleep_disabled`，不是第一个，而且**写不进去就失败**：
（a）某个参数写完**读回来不是 0**，（b）**根本没有**这个参数。这两条不是修辞：

* 第一条是 `install-no-edl-on-panic.sh` 里同一个形状的教训——那一个策略**清掉每一个** `download_mode`
  而不是清一个，理由相同；
* 第二条是 `install-cpufreq-governor.sh` 记录在案的缺陷——一个 applier 因为 `echo` 返回 0 就把写入
  记成完成，于是**修复被报成已武装、unit 显示 `active`、而什么都没变**。

`--remove` 反过来做：disable unit、删掉两个文件、把参数**放回 1**。

**它不碰的东西**，applier 自己也说一遍：不动梯子自己的节点、不 enable/disable 任何 cpuidle 状态、
不写任何 thermal trip point、不设频率、不碰 keeper 与 governor（那是另外两个修复，它们有自己的安装器）。
**不刷任何东西，不打开任何块设备，不重启。**

## 6. 它接进"一次开机"了，而且**执照是这一次运行写出来的那个文件**

`scripts/host/zl1-one-boot-runbook.sh` 的步骤表现在是**六步**：

```
01-capture  02-panic-guard  03-heat-chain  04-fingerprint  05-trial  06-lpm-fix
```

顺序仍然是**被强制的**，而 06 只是把理由补完：

* **01 先**，因为 keeper 的 pid、tick 和 netwatch 日志在 03 退休它之后就不存在了；
* **02 在一切可能 panic 的东西之前**，而且它是**唯一**活过这次开机的一步——06 的第二个前提就是它；
* **03 在 05 之前**，因为退休 keeper 正是把实验的前提 C 武装起来的那件事；
* **05 是只读的**；
* **06 最后，因为它的执照就是 05 的输出。**

而 06 的参数是 `--after-trial $OUT/05-trial.txt`——**这一次运行刚刚写出来的那个文件**。harness 断言的
**恰好是这一点**（它从 runbook 的调用表里取出第 6 行的那个参数，再和**本次运行自己**的归档目录比），
因为指向一份**旧**归档的执照，是**另一次开机**的执照。

**而 06 之所以是一步、不是一个 flag**，也和 `--apply-trial` 的区别有关：`--apply-trial` 是**实验**
（写参数、测、然后放回去），**06 是让实验的答案活过这次开机的那次安装**。一次停在 05 的运行，
**量了第三因，然后把手机又留成热的**。

## 7. 这一轮**不**声称什么

* **不声称散热解决了。**它声称的是：**第三因现在有一个被授权的、会持久的安装器**。
  它**一次都没有在真机上跑过**——连 unit 都没在真设备上装过。
* **不声称那三个修复里的任何一个跑过。**三个都还没有。这一页把第三个从"缺口"变成"有工具"，
  而"有工具"不是"有效果"。
* **不声称"参数可写"等于"有效"。**那条推理正是这个安装器**拒绝**接受的那条，它要的是实验的输出。
* **不声称实验的结果是什么。**那个结果是**设备**说的，而设备还没跑过它。安装器把四种"不该装"
  逐一点名，就是为了让"还没跑"不会被读成"可以装"。
* **不声称装上之后开机还起得来。**把梯子放开之后 CPU 会真的进低功耗状态，而**低功耗状态在真机上
  是不是稳定**，是这次安装要冒的险——这也是为什么 02 必须在它前面。
* **不声称 `--remove` 已经被演练过。**它在 harness 里被断言（disable、删两个文件、参数回到 1），
  **不在设备上**。

## 8. 这一轮自己找出来的四个缺陷，而**四个都不是假警报**

家族在内容冻结之后第一次跑是**红的**，红在四个地方。四条都值得记，因为它们是这个工程**最贵的那类**
缺陷的不同面：

| 红在哪 | 是什么 | 为什么它真的会咬人 |
|---|---|---|
| cli-usage 的"每个脚本可执行" | 新脚本**没有 exec 位** | 一个 `bash SCRIPT` 能跑而没有 exec 位的脚本，会在真正需要 `./SCRIPT` 的那一天失败——而这个仓库的被测脚本会被**复制到设备上**跑 |
| cli-usage 的散文扫描 | `zl1-installers-selftest.sh` 的一条**注释**里的 `\`--value\`` 被执行了 | 双引号里的反引号是**命令替换**：这次它只是把 `--value` 当命令跑了一遍并失败，而下一次同样的形状可能真的运行**别的**东西（docs 122 里这个形状在设备侧咬过一次） |
| cli-usage 的引用 | health-check 写着 214，实跑 216 | 就是这一页在算的两个数：**页面新点名一个脚本**，而新点名的那个脚本必须能印自己的 header |
| **家族 meta-harness 的第 7b 节** | 我在实验 harness 里新写的那一圈断言用了 `printf … \| grep -q` | **这就是 docs 134 记下来的形状**：`set -o pipefail` 下，`grep -q` 命中后立刻退出，写端还没写完就被 SIGPIPE 杀掉，**pipefail 把写端的死报成这条检查的答案**。这次 haystack 小，所以它是一次**竞争**（有命中有红有绿），而不是每次必红——**而"有时红"正是没人能据以行动的检查**。改成 here-string（`grep -Eq -- … <<< "$VSRC"`）之后它消失了 |

**第四条是本轮最值得记的一条**，因为它是这个工程**自己抓到自己**：第 7b 节存在的理由就是"扫描每一个
设了 pipefail 的 harness，看有没有这个形状"，而它**扫到的正是同一轮里新写下的那一处**。
这也是为什么它是**扫描**而不是一句声明——一条声明不会红。

## 10. 设备状态与下一步

整轮**没有写设备**：没有挂载、没有写镜像、没有 flash、没有一条会改变设备状态的命令。

**而"设备在 fastboot"这句话，这一轮没有重新读过。**它是从 docs 149 一路被抄下来的同一个读数，
而**今天这台笔记本的 USB 上什么都没有**（`lsusb` 里连 `18d1:` 都没有）——因为设备被拿去墙充了。
这两件事都不是故障，它们合起来是这一页要记的形状：**一句关于设备状态的断言，在没有人重读它之后
