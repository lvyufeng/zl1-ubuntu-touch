| 问题 | 答案 |

## 2. 为什么第三个窗口不是"多做一个"，而是这个实验能不能成立的问题

三个成因装上之后的只读稳态读数（docs 164 的存档）：

```
busy 0.80 of 4 cores;  hottest: tsens_tz_sensor9 50.9 C
top: systemd-journal 6.00/s, rcu_preempt, rcu_sched, sensorfwd, ksoftirqd/2, zl1-netwatch.sh 0.85/s
```

而同一台机器在**没有任何改动**的情况下，两次只读窗口（相隔约一小时）报出的**最热 tsens zone** 是
**45.6 °C 然后是 50.9 °C**——而且这两次里"最热的那一个"还不是同一个传感器
（先 `tsens_tz_sensor17`、后 `tsens_tz_sensor9`；存档里那次是 [`evidence/three-heat-causes-installed-steady-state-2026-09-25.log`](evidence/three-heat-causes-installed-steady-state-2026-09-25.log)）。
这就是 A/B 两个窗口的致命处：5.3 °C 的漂移比这个成因本身可能还大。
第一版设计只做 A/B，等于把"手机在自己变热"记在阶梯头上——**而那个数字会看起来非常像结论**。

（同一份存档还顺带说明"这台机器的温度"不是单个数：**同一个瞬间** tsens 各 zone 之间就差了
45.6–50.9 °C 这么多。上一段那条漂移读数的完整证据是上一轮设备上的两个窗口，
只有后面那一个在存档里；写在这里的是这两次报出的**最热值**，不是一个传感器的两个时刻。）

所以第三个窗口 C 是**同一个状态再做一次**：它不是重复，它是**判据**。
`contaminated` 那条分支的全部意义是：让"我量到的不是这个成因"成为一个**可以到达的结果**，
而不是一句写在文档里的注意事项。

## 3. Verdict 与退出码

| verdict | 条件 | 退出码 | 说的是什么 |
|---|---|---|---|
| `cost-measured` | B 比 A 高 ≥ 0.2 °C，且 C 比 A 高 < 一半 | 0 | 在这个负载下，这是第三因在**温度**上的价钱 |
| `no-detectable-cost` | B 比 A 高 < 0.2 °C | 0 | 这台实验分辨不出来。**脚本反对自己**——第三因的价值在深状态计数器里（docs 164），不在这几个 zone 上 |
| `contaminated` | C 比 A 高 ≥ B 比 A 高的一半 | 1 | 动的东西没有跟着阶梯回来：**关于这一趟的陈述，不是关于阶梯的** |
| — | 两个最大值都比不出（没有 tsens zone 三个窗口都可读） | 1 | 没有表就没有读数，**不是**打印一堆 0 的差 |

其余退出码沿用这条链的约定：2 = 不是这台设备（`compatible` 里没有 `msm8996`），
3 = 拒绝（A/B/C 三个前置条件之一不成立，**一个字节都没写**），4 = 写已经发生、写完之后出了问题（trap 已经试着还回去了）。

## 4. 安全模型：为什么不靠"小心"，靠"只有一个文件可写"

`host/zl1-lpm-ladder-trial-selftest.sh` 对**第一个**写设备的脚本立过一条规矩（docs 122）：
只读探针可以靠"不往 `/sys` 重定向"来守，会写的脚本不行，所以守的是**白名单**——
把 shipped 源码里**每一个重定向目标**抽出来，必须是参数文件或脚本自己 `mktemp` 目录里的东西。
这一页的仪器照抄了这条，harness 的 section 0 和变异 m0 都跑同一段检查。

三条拒绝，**都在任何写之前**：

| | 条件 | 为什么它是一条拒绝而不是一句警告 |
|---|---|---|
| **A** | 仪器可读（`--thermal PATH`） | 它同时拥有 zone 表**和**它的单位约定（三个约定同时在一个瞬间），第二份拷贝就是第二次搞错的机会（docs 96） |
| **B** | 参数存在、且**可写** | 先做**同值写入证明**：把当前值写回去再读，读不回来就说明这个文件事实上不可写（模式位只是模式位）。docs 163 的教训是"比较字母表会在写成功之后才报告失败"，所以这只证明**可写**，不证明字母表 |
| **C** | 当前状态是**OFF**（`0`/`N`） | 窗口 A 必须是"修按装机状态的样子"。已经是 1 的话，A 就不是基线，量出来的差值是关于**上一次开机**的 |

**字母表**（docs 163）：`sleep_disabled` 是 bool 模块参数，文件里**存**的是 `0`/`1`，内核的 sysfs `show` **渲染**成 `N`/`Y`。
所以脚本里只有两个函数 `is_off`/`is_on`，**任何地方都不把读回来的值和写进去的字符串比**。
这一条在同一个仓库里已经犯过一次（装机器拒绝了自己成功的写入），所以它是**写在头上的规则**，不是注释。

## 5. 写 harness 时找出来的真缺陷：`TERM` 恢复完，shell 还会继续跑

第一条真正重要的发现不是关于温度的，是关于**退出**的。

仪器的 trap 原来是 `trap 'do_restore' EXIT INT TERM HUP`。POSIX sh 的语义是：
**信号被 trap 之后，shell 从被打断的那条命令继续往下跑**（不退出）。于是：

1. harness 在 `--settle 3` 的窗口里杀掉运行；
2. handler 把参数写回 0，印出 `[trap] … verified by read-back.`；
3. **shell 继续**：跑完窗口 B、写 0、跑窗口 C、印 verdict、印 `the state it started in`；
4. 退出码 **0**。

也就是说：一次**被打断的实验**报告自己是一次**完整的实验**，而且它最后那句"回到开始时的状态"
之所以为真，只是因为它跑到了最后——**它覆盖掉了自己刚刚做过的恢复**。
harness 的第一版正是这么断言的（`[ "$BG_RC" != 0 ]` 判"被打断的运行必须非零退出"，红了），
而它红的方式值得记下来：**它红在了一个看起来像 harness 自己错的断言上**。

修法在 shipped 源码里：

```sh
on_signal() {
  do_restore
  exit 130
}
trap 'do_restore' EXIT
trap 'on_signal' INT TERM HUP
```

`do_restore` 只在**自己的读回**说"恢复成立"的时候才清 `WROTE`：所以恢复成功之后，随后的 EXIT trap（另一个 trap，它照样会跑）没有东西可还、不会写第二次；而恢复**没成立**的时候那个 EXIT trap 会再试一次（有界：一个信号 handler + 一个 exit trap），下面那句"trap 会再试"才是真的。

**第二个版本仍然是错的，而且错得更隐蔽**：harness 改成"杀在第 2 秒"，
结果这次**过了**——因为窗口长度和 settle 的巧合刚好让它落在被挡住的窗口里。
一个靠定时器落点的断言是一个**没人能据此行动的断言**（这个仓库已经记过一次，
`zl1-a-flake-must-be-pinned-with-its-input`）。所以现在是：harness **轮询参数文件**，
等 subject **自己的写入**出现（`fp_raw` = 1）再杀——杀在"阶梯确实被挡住"这个**已知状态**里。
那是唯一一个"运行死掉会留下一个实验"的窗口，也正是 trap 存在的理由。

## 6. harness：五个一开始是假的断言，最后一个不是被断言抓到的

`host/zl1-ladder-temp-ab-selftest.sh` 85 条检查，结构沿用这个家族（stub 目录**就是**设备、
沙箱 `PATH`、两趟伪根改写、变异必须变红）。写的过程中有五个断言/写法是**假的**，全部记在这里：

| 假在哪 | 为什么假 | 怎么变成真的 |
|---|---|---|
| 参数回没回位 | fixture 里**文件存**的是 `N`/`Y`，而脚本写进去的是 `0`/`1`——于是每一次"它回位了吗"都在拿**存着的 0** 和**渲染出来的 N** 比。这正是 docs 163 的形状，出现在一篇**在它之后**写的 harness 里 | `fp_set` 按设备**存储**的方式写（`fp_set N` 落一个 `0`），`fp_now` 走 `tr` stub 渲染，`fp_raw` 专门给"存了什么"那一条断言；tr stub 有三条校准探针（渲染 `0`→`N`、`1`→`Y`、非参数文件要**转交**真 tr），否则每个字母表场景都会在测一个纯文本文件时通过 |
| 同值写入证明"在源码里" | `want` 的**第二个参数是文本**，不是文件——传进去的是**路径字符串**，于是它拿模式和路径比 | `cat` 进来，并在注释里写明这条 |
| 同一个断言的另一面 | GNU grep 里，**ERE 中间的裸 `$` 不匹配字面的 `$`**：模式 `` printf '%s' "$P" `` **不**匹配文本 `` printf '%s' "$P" ``（写成单引号里的 `\$` 就匹配）。这是**实测**出来的，不是推的 | 模式改单引号 + `\$` |
| 白名单"没有额外写入" | 它只认**带引号**的目标。于是 shipped 源码被报了 **6 个**越界目标（全都是它自己散文里的 `->` 箭头被读成写入），而加了一个**不带引号**的第五个目标的变异体报了 **0 个** | 不引号形状只收**看起来像路径**的（`/` 或 `$`），并把 `/dev/null`、`/dev/stderr`（水槽，不是状态）列进白名单 |

| **`want` 自己** | 这个 harness 设了 `pipefail`，而它的 `want` 是 `printf '%s\n' "$2" \| grep -Eq "$1"`——**docs 134 记过的那个形状**：`grep -q` 一匹配就退出，写者被 SIGPIPE 杀掉，pipeline 的状态变成**写者的死**（141），一个"里明明有"的断言会随机变红。**这一条不是被这个 harness 的任何断言抓到的**，是**family 自己的不变式那一节**（section 7b）抓到的：它扫所有设了 `pipefail` 的 harness，禁止把早退的读者放在管道右边。同一个阶段里 `zl1-lpm-ladder-trial-selftest.sh` 已经改成 here-string 形式了，而**在这之后写的** harness 又退回旧写法——这正是那条不变式存在的理由 | 改成 `grep -Eq -- "$1" <<< "$2"`（干草堆**直接**交给读者，管道里没有写者进程），`wantsq` 同理 |

第三个变异（m0）的教训值得单独说：**一个"变异没被看见"的假绿，比一个失败的断言危险得多**——
它看起来是"检查生效了"。所以 section 0 现在有两个方向的断言：shipped 源码必须是 0 个越界，
而那个**加了**目标的变异体必须是 1 个，并且那个路径要在报告里**被点名**。
