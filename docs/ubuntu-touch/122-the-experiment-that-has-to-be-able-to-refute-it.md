## 1. 一句话结论

| 问题 | 答案 |
|---|---|
| 这一轮做了什么？ | 把"**写 0 到底有没有用**"做成了一个**能跑、能量、能退、也能反驳自己**的实验，外加 **131 检查**的离线 harness |
| 为什么需要一个实验？ | 因为 §5.5 的结论只到"**这个文件可写**"为止：**0664 证明文件能写，不证明写下去有用。**"写 0 之后阶梯是否真的回来"是设备上的前后对比，没有别的证据能代替 |
| 它写什么？ | **一个文件**：`/sys/module/lpm_levels/parameters/sleep_disabled`。写 `0`，量完，**再放回 `1`** |
| 有哪三道门？ | 三个**前置条件**，每一个都是一次**拒绝**（exit 3，什么都不写），而不是一句警告：**(A)** panic→EDL 必须已经解除（`download_mode=0`）；**(B)** cpuidle 计数器必须可读；**(C)** 不能有 debug keeper 在跑 |
| 为什么 (A) 是拒绝？ | 因为在这台设备上一次 hang **不是 hang，是一次 EDL**，而 EDL 只能靠**物理长按电源 10–20 秒**结束（[`49`](49-*.md) §6）。区别就是"hang 会变成重启"和"hang 要花一根手指"。有了 (A)，这个实验就**不需要**论证自己不会 hang |
| 为什么 (B) 是拒绝？ | 整个实验就是计数器上的前后对比。**读不到不等于 0**，而这里的一个 0 看起来**正好**像"阶梯开了但一次都没进"——那会把一次读失败变成一条结论 |
| 为什么 (C) 是拒绝？ | keeper 每秒 `systemctl` 一次，占住约一个核（docs 72/94/99）。**一个从不停下来的核不会进入深 idle**，所以此时"深档没有时间"是**关于 keeper 的读数**，不是关于参数的。`--allow-keeper` 可以强行跑，判决会把它标成 **CONFOUNDED** |
| 怎么保证写坏了能回来？ | ①**先证明写路径**：把当前值**写回它自己**再读，读不回来就停，且**此时什么都没改**；②undo 是一条**写在设备上**（`/tmp`）的一行命令，因为最常见的失联方式是 netwatch 重新枚举 USB（docs 118）——**丢掉会话不该丢掉 undo**；③`trap` 在**每一条**退出路径上（正常结束、出错、INT/TERM/HUP）回写；④**故意没有后台计时器**：这个值本来就活不过重启，所以"丢会话"不是一个需要补救的状态 |
| 判决能推翻自己吗？ | **能，而且是设计目标。**判决是一个 2×2（写之前深档进过没有 × 写之后进过没有）外加一次**机会检验**，四种答案是 **REFUTED / SUPPORTED, NOT PROVEN / INCONCLUSIVE / CONFOUNDED**。其中 REFUTED 的意思是"**写之前深档就已经在被进入了**，所以 `sleep_disabled=1` 根本没有关住它"——假说当场死掉，不管后半段量到什么 |
| 离线验证？ | `zl1-lpm-ladder-trial-selftest.sh` **131 检查 / 0 失败 / 0 SKIP**；安全模型是**白名单**（见 §5），不是被削弱的黑名单 |
| 家族全量跑呢？ | **17 个 harness / 1867 检查 / 全绿**（§7） |
| 动设备了吗？ | **没有。**这个实验**从来没有在设备上跑过**；设备仍在 EDL |

## 2. 为什么"能写"还不够

[`121`](121-the-third-question-about-the-heat.md) §5.5 的更正把一件载重的事翻了过来：
`lpm_levels.sleep_disabled` **不是**内核的 `__setup` 启动参数，而是**内置 `lpm_levels` 驱动的模块参数**，
权限位 **0664**。于是修法从"换 cmdline → 新 boot 镜像 → **一次 flash**"变成
"**一次运行时写入**"。

但那个更正自己就写明了它的边界：

> **`0664` 只证明这个文件能写，不证明写下去有用。**

而且这个边界不是可以绕过去的谨慎，它是**事实**：

* 一个 `perm` 位是**内核的注册信息**，它说的是"sysfs 上会有这个文件、写它会调用驱动的 `set` 回调"；
* 它**不说**那个 `set` 回调会做什么。回调的语义**在源码里，而源码不在这台设备上**；
* 于是"写上 0 之后，SoC 的低功耗阶梯是否真的开始被使用"只能由**行为**回答：cpuidle 的
  `usage` / `time` 在写入窗口前后的差。

**这就是这一轮存在的理由**：把一个已经在纸上成立的判断，变成一次可以在**同一个 boot 里做完、量完、退回来**的实验。

顺带一个让这件事便宜得多的事实：**这个值不持久**。下一次 boot 会从 cmdline（那条
`lpm_levels.sleep_disabled=1`，原厂就带着，v63 逐字继承）把它设回 `1`。所以：

* 实验的作用域**由构造决定就是一个 boot**；
* 跨重启没有什么"要放回去"的东西，**重启本身就是逃生口，也是 undo**。

## 3. 三道门，每一道都是拒绝

`--apply` 在写任何东西之前先检查三件事。**每一件不合格就 exit 3，什么都不写**——
不是"警告一下继续跑"，理由各自不同：

| 门 | 检查什么 | 不合格时会发生什么（如果不拒绝） |
|---|---|---|
| **A** | `download_mode == 0`（`/sys/module/*/parameters/download_mode`，**按 glob 找，不按名字**——理由原本写的是"docs 86 记过电源驱动的名字和字符串搜索的猜测不一致"，**那句话是错的**：86 记的是"**应是** `msm_poweroff`、**没在真机上确认过**"，而真机读到的就是 `msm_poweroff`，猜测被确认了。glob 仍然对，诚实的理由是**鲁棒**；见 [`125`](125-the-device-read-those-four-things-already.md)） | panic 会**武装 EDL**（镜像默认就是 1）。在这台设备上 hang 不是 hang，是一次只能**物理长按电源 10–20 秒**结束的 EDL（docs 49 §6）。差别就是"hang 变成重启"和"hang 要花一根手指"——**有了这道门，实验不需要论证自己不会 hang** |
| **B** | 至少有 CPU 暴露 `cpuidle` 目录（按**目录**数，一个没有 cpuidle 目录的 CPU 不是"计数器为 0 的 CPU"） | 整个实验是计数器上的前后对比。**读不到不等于 0**，而这里的一个 0 长得**正好**像"阶梯开了但一次都没被进入"——一次读失败就变成了一条结论 |
| **C** | 没有 v63 debug keeper 在跑（**按 argv 匹配**，一个命令行里只是**提到**那个路径的 shell 不是 keeper） | keeper 每秒 `systemctl` 一次，占住约一个核。**一个从不停下来的核不会进入深 idle**，于是"深档没有时间"是**关于 keeper 的读数**。这正是它必须是**拒绝**而不是警告的原因：换一个说法，"这次读数是关于 keeper 的"就等于"这次什么也没量到" |

另外还有**一件只报不拦**的事：最深的那个 cpuidle 状态是不是被 `disable` 了。
一个被那个**另一套机制**关掉的状态，本来就**不该**对本次写入有反应，
所以那种情况下判决说的是 **CONFOUNDED**，而不是从"没动"里推出任何结论。

`--allow-keeper` 是唯一的强行入口，它做两件事：放行，并且**在判决里写明这次读数是 CONFOUNDED**。

## 4. 实验的形状，以及它怎么才能说出"你错了"

顺序是这样的（`--apply`）：

| 步 | 做什么 | 为什么是这个形状 |
|---|---|---|
| 1 | **三门前置检查**，全部通过（或有记录地放行）才继续 | 拒绝的代价是 0：什么都没写 |
| 2 | 打印参数的**值和权限位** | 权限位（0664）正是这个实验存在的理由（docs 121 §5.5） |
| 3 | **BEFORE 读数**：每个核每个状态的 `usage` / `time` | 这一半才是**能反驳**的那一半：如果深档**在写之前就已经在被进入**，参数就不是它的门，假说当场死 |
| 4 | **同值写入证明**：把当前值**写回它自己**再读 | 一个写不进去（或读不回来）的 sysfs 文件，应该在**还没有改变任何东西**的时候被发现，而不是在依赖它之后 |
| 5 | 把 undo 写到**设备上**的 `/tmp`，然后**写 0**，并读回 | 常见的失联方式是 netwatch 重新枚举 USB（docs 118）；操作者手上还有 shell 的时候，不该需要背路径 |
| 6 | **settle**（默认 120 s，`--settle` 可改）后取 **AFTER 读数**，逐 (cpu, state) 求差 | 差是 **per-key 联结**出来的，两边任何一个**读不到**都印成 `NOT-A-NUMBER`，**绝不当成 0**——这个实验整个就转在"0"这个读数上，它不能被一次失败的读**制造**出来 |
| 7 | **回写 1**，并读回验证 | 读不回来就 exit 4，并叫操作者跑 `--revert`；不声称做过一次没做成的回退 |
| 8 | **判决** | 见下 |

判决是一个 **2×2 加一次机会检验**，四句话各自点名它来自哪条读数：

```
        写之前深档进过吗？  ×  写之后深档进过吗？
   再加一问：窗口里"有机会空闲"吗（最浅那档的 usage 动过吗）？
```

| 判决 | 条件 | 它说的到底是什么 |
|---|---|---|
| **INCONCLUSIVE** | 深档的差读不到 / 最浅档的差读不到 | 关于**仪器**的答案（exit 1），不是关于手机的 |
| **REFUTED** | 深档**在写之前就已经进过** | **假说死掉**：`sleep_disabled=1` 没有关住那个状态。**后半段量到什么都不能改变这件事** |
| **SUPPORTED, NOT PROVEN** | 深档**写之前 0 次**、写之后 > 0 次，且最浅档动过 | 与"这个参数是那扇门"**相符**，但**不是**证明：这里没有任何东西在量"同样的机会在写之前会不会也进深档"，而参数语义的源码不在这台设备上。**它真正定下来的是：这台设备的阶梯是可达的**——这一点在本仓库的所有镜像里都还没有被证明过 |
| **NOT SUPPORTED** | 最浅档动过（**确实有空闲机会**）、深档仍然是 0 | 要么参数并不关住它看起来关的那件事，要么这颗 SoC 的阶梯还缺别的东西。**不许把它当成"修好了"** |
| **CONFOUNDED** | 任何一条被上面那两件"只报不拦"的事（keeper 在跑／深档被 disable）解释得通 | 这次读数**不是答案**（exit 1），而且**在输出里写明**，不留给读者自己发现 |

**REFUTED 是一个场景，不是一个段落**——harness 第 11 节就是让它真的发生。

退出码（`--help` 里写着，harness 逐条对着源文件断言）：

```
0  量到了（REFUTED 也算量到了，它是反对这个脚本要试的东西的读数）
1  INCONCLUSIVE / CONFOUNDED —— 关于这次实验的答案，不是关于手机的
2  不是 zl1
3  REFUSED —— 某道门没通过，什么都没写
4  写入发生了，之后出了事（状态与 undo 都打印，trap 已经试图回写）
```

## 5. 安全模型：白名单，而不是被削弱的黑名单

这是本仓库第一件**故意写设备**的脚本，所以它不能沿用别人的安全线。
只读探针的守卫是"不许往 `/sys` 里重定向"；这一件**合法地**就有一条重定向，
如果照着写，那条黑名单就要被**削弱到允许一次重定向**——而**被削弱的黑名单就是后来的编辑会走进去的那扇门**。

所以规则换成一个**白名单**：**发出去的源码里每一个重定向目标，必须恰好是点过名的那些**。

```
/sys/module/lpm_levels/parameters/sleep_disabled     ← 唯一的设备写入
/tmp/zl1-lpm-trial-revert.sh                         ← 设备上的 undo
/tmp/zl1-lpm-trial-before  /tmp/zl1-lpm-trial-after  ← 两个计数器快照目录
/tmp/zl1-lpm-trial-deltas                            ← 差值文件
```

harness 第 0 节把这个集合从源码里抽出来，两个方向都断言：**非空**，且**不含没声明过的**；
并且**一次注入第五个目标必须让它变红**。

抽取器有两个已知的盲点，harness 里写明而不是留给人发现：

* **变量目标对任何正则都是不透明的**——`printf 0 > "$s/disable"` 和一次读，在不知道 `$s` 是什么的情况下**无法区分**；
* **`->` 里含一个 `>`**，所以箭头必须先删掉（散文里的箭头不是重定向），而真正的重定向仍然必须被抓到。

比静态检查更强的那一条是**行为检查**：跑完之后，**假设备逐字节不变**——
结构 + 大小 + 每个文件的 md5。这一条在本轮里必须写得更小心一点，因为它比较的是"**一次故意写入的运行**"：

* 运行**有权**动的路径正好三类：undo 文件（新出现的）、参数本身（`0` 又回到 `1`）、以及 **cpuidle 计数器**；
* 计数器的理由值得单独记：它们的差是 **stub 的 `sleep` 造成的**——也就是**假设备在窗口里做了一件事**。
  那是**测量**，不是脚本的写入；
* 一条正则分不清"设备自己动过"和"脚本写过"，所以这个豁免必须靠**第二条**检查守住：
  **相差的路径集合必须恰好等于这三个集合**。别处多写一个文件——或者在豁免的那棵树里写一个
  （比如某个 `state*/disable`）——仍然红。

## 6. 造它的时候抓到的缺陷

**仪器（`device/zl1-lpm-ladder-trial.sh`）上的两条**，第二条是本轮最值得记的一条：

| 缺陷 | 它本来会造成什么 |
|---|---|
| 最深档的编号取自 **cpu0 的名字** | 于是每一个判决都是关于**最浅**那一档的陈述。实验在测错的东西，而输出里没有任何一行说它测错了 |
| `: > "$DELTAS"` —— 重定向失败时**shell 当场死掉**，退出码 **2** | dash 里 **`:` 是特殊内建**，重定向错误对它**致命**：shell 立刻以 2 退出，**在脚本自己的检查能跑之前**——而这个脚本把 2 定义成"**不是 zl1**"，于是**退出码在撒谎**。trap 仍然正确回写了参数（这一半是好的），但没人知道为什么退出码是 2。现在用 `printf`：它是**普通内建**，失败是**要检查的状态**而不是一次死亡。**这是量出来的，不是推出来的**：把 deltas 路径指向一个目录，就复现了 2 |

**harness 上的若干条**（都属于"一个通过了的、但什么都没测的测试"这个形状）：

* **fixture 里 `printf '\$DFU\n'` 用了单引号**，于是假设备里躺着字面量 `$DFU`；
* **backticks 出现在双引号的 `say` 串里**，于是 shell 在判决**打印到一半**的时候去执行了
  `sleep_disabled` 并打出 "not found"；
* **`--status` 曾经会写 before 快照**——最该只读的那条路径上写了一个文件；
* **helper 定义在被使用之后**，于是 `bad: command not found` 让整整一节**静默失效**；
* **citation 抽取器是 `grep -oE '[0-9]+'`**：它匹配到的是 `zl1-…` 里的那个 `1`，
  于是把 `124 checks` 读成 "1"（当时的计数是 124），宣布了一次并不存在的漂移。**名字必须先匹配，数字从它后面取**；
**顺带抓到的一条，在 `zl1-health-check.sh`（不是这一轮的脚本，但只有这一轮的运行把它暴露了）：**
仓库根目录里出现了一个空的、名叫 `file` 的文件。追下去是——**健康页在"执行"它自己的散文**。
**双引号里的 backtick 就是命令替换**，于是那七处加重的短语，在各自那一行被打印的时候**真的被当成命令跑了**：

| 写的是 | 发生了 |
|---|---|
| `` `/` `` | `bash: /: Is a directory`，而且**打印出来的那句话里那个字符消失了** |
| `` `tr \| grep \| sed \|\|` `` | 一个不完整的命令，替换失败，**那一行剩下的字被整段丢掉** |
| `` `nsenter -m -- test` ``、`` `systemctl --user status` `` | **在 host 上真的跑了这两条命令**——由一个"只读"为存在理由的页面 |
| `` `: > file` `` | **在仓库根目录建了一个文件**（就是那个 `file`） |

散文里的 backtick 现在都被转义，而且两条症状都**行为化**地钉在"跑这个页面的那个 harness"上
（在自己的目录里跑、stderr 单独接出来，两者都必须为空），再加一条静态规则：
**散文里不许有未转义的 backtick，打不打印都不许**。
**这条静态规则在写它的当下，就在"记录这个缺陷的那两行"上失败了**——同一个坑，两次，
就在描述它的文字里。这大概是它有效的最好证据。

**然后把这个形状在整个仓库里扫了一遍，抓到一个真的，而且是在设备侧的**：
`zl1-modem-probe.sh` 里那句讲 glob 没有展开的 `say`，把 `cat` **当成命令跑了**——
**`cat` 不带参数会读 STDIN**。量出来的结果：用一个带数据的管道喂进去，
**打印出来的句子里夹着管道里的内容**，而 `cat` 这个词不见了。
在设备上这意味着它会**吃掉 ssh 通道的输入**，并把吞下去的东西**打印进这次探测的输出**——
也就是进了那份要归档的证据文件。已经转义。

**这类检查现在是仓库自己的一条检查了**（`zl1-cli-usage-selftest.sh` 第 4e 节），而且它**不是**对
backtick 做 grep，是一条**引号状态机**：这棵树里有**四种合法写法**是朴素 grep 会报成缺陷的
（`<<'EOF'` 引号 heredoc、双引号字符串里 `$( )` 中单引号里的 backtick、以及已经转义过的），
六个 fixture（两个会执行、四个不会）**每一条都断言**，所以这条检查**不会被它自己的噪声关掉**。
同一轮扫描还发现四个 harness 里有 **12 行 fixture 本体**在 heredoc 写出时被执行（都是注释行，
所以只让 fixture 的说明文字变成了空，但同一个坑）。

**这条静态规则在写它的当下，就在"记录这个缺陷的那两行"上失败了**——同一个坑，两次，
就在描述它的文字里。这大概是它有效的最好证据。

* **"一次成功的写又被吞掉"的场景在本机不可达**（`chmod a-w` 之后普通用户写不进去，所以那是
  "写被拒绝"而不是"写了不生效"）。它**明说 SKIP 并被数出来**，同时把可达的那个邻居
  （**写入被拒绝**，用 0444 文件构造）**真的测了**；不可达的那条分支改为**在源码上钉住**，
  这样后来的编辑把它删掉仍然会被抓到。

## 8. 这一篇**不**证明什么

* **不证明 `sleep_disabled` 就是发烫的原因。**它连"这个参数关住了阶梯"都还没证明：
  这里证明的是**实验可以跑、能量、能退、能反驳**，而**设备上还没跑过**。
* **不证明任何设备侧的读数。**`--status` 在设备上从没跑过；`--apply` 更没有。
* **不证明参数不出现时该怎么办。**如果 `lpm_levels` 在这个 boot 没注册，
  脚本说"这个 boot 上跑不了"并**把它当成答案印出来**（不是当作故障解释掉）——
  但那条分支在真机上从没被走到过。
* **不证明这个实验安全。**它的安全性来自三道门和"值不持久"这两条结构性事实，
  不来自任何一次真机运行。

## 9. 设备状态与下一步

整轮没有动设备：没有写任何分区或 boot，没有跑 QDL/QFIL，没有重启，没有绕过权限。
设备仍在 **Qualcomm EDL**（`05c6:9008`，无序列号）；唯一的出口是**物理长按电源 10–20 秒**（只有用户能做）。

设备回来的那一次，顺序是：

```
# 0. 先出 EDL：物理长按 POWER 10–20 秒，等 RNDIS 和 ssh
scripts/host/zl1-post-recovery-capture.sh            # 只读：0 系列（含 04b modem / 04c sleep）
scripts/install-no-edl-on-panic.sh --install         # ← 门 A，而且它是这一串里唯一跨 boot 的一步
scripts/host/zl1-heat-fix-chain.sh --status          # 只读：发烫链条的四个问题
scripts/host/zl1-heat-fix-chain.sh --yes             # 前两个修复：governor + 退役 keeper
scp scripts/device/zl1-lpm-ladder-trial.sh root@$IP:/tmp/ && \
  ssh root@$IP 'sh /tmp/zl1-lpm-ladder-trial.sh --status'
ssh root@$IP 'sh /tmp/zl1-lpm-ladder-trial.sh --apply'   # ← 这一步是一次决定，不是一次读数
```

**顺序本身是这一轮改掉的一个缺陷。**`install-no-edl-on-panic.sh` 有两半，而它们**不一样**：

| | 写什么 | 活多久 |
|---|---|---|
| `--capture-only` | pstore → `/userdata` | **这一个 boot** |
| `--install` | 上面那一半 **+ 一个每次 boot 都写 `download_mode=0` 的 unit** | **跨 boot** |

它是这一串写入里**唯一一个让"下一个 boot 更安全"的动作**，而它恰好也是本实验的门 A。
一次手指换来的那个 boot，是最值得把它装上的时候——**装一次，之后每个 boot 都自动满足门 A**。
可是 capture 打印的"接下来做什么"里，那一行原本只写着 `--capture-only`（也就是**不装策略**的那一半）。
这已经修了：两半现在分开点名，并且写清楚哪一半更久、为什么值得先做，
同时把 doc 86 那句警告一起带上——它**降低概率，不移除路径**，任何地方都不许引成"EDL 不会再发生"。

****这一串现在是 `scripts/host/zl1-one-boot-runbook.sh --yes` 一条命令**（[`124`](124-the-boot-a-finger-bought-is-one-command.md)）：
顺序被强制执行，而第 05 步在这个序列里的位置**不是"放最后方便"**——门 A 由第 02 步满足、门 C 由第 03 步满足，
所以**只有那里它才可能通过**。`--apply` 本身仍然是**单独的一次决定**（runbook 里是 `--apply-trial`），
不是一件可以顺手做的事。**
在它跑之前，`--status` 会先把三件事读出来（`download_mode`、cpuidle 是否可读、keeper 在不在），
`--explain` 会把每个读数决定什么讲一遍——两者都**不写一个字节**。

在那之前，这一篇里的一切仍然只是**离线可以核对**的东西。
