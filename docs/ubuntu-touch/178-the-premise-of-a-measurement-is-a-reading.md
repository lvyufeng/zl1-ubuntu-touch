# 178 — A/B 的前提是一台**设备的读数**，不是一次调用的位置

**日期**: 2026-09-26
**状态**: **只改了链和它的 harness；设备上一次都没跑过**。这一篇是
[`177`](177-the-window-is-the-unit.md) 之后**没有在仪器里**继续往下挖的那一半：docs 177 修的是
"一个窗口的温度是多少"和"一个速率除以谁"；这一篇修的是**那个差值的资格**——

它是从**调用位置**推出来的，而调用位置**说明不了**这件事。

## 1. 一句话结论

| 问题 | 答案 |
|---|---|
| 这一轮发现的缺陷是什么？ | 链印出来的那句 **"window A is before either fix, window B after both"** 是**断言**的，不是**读出来**的。它由**调用位置**推出：A/B 在第一步修复之前启动，所以窗口 A 就是"修复前的手机"。 |
| 为什么这句话现在是**假的**？ | 因为**两个修复都变成了开机 unit**。今天这台手机**每一次开机都会自己把两半装上**：`keeper: gone`、四个核全是 `interactive`。于是窗口 A = **修好的手机**、窗口 B = **修好的手机**，两者之差是**手机自己的漂移**——由一个工作正常的仪器印成**价钱的形状**。 |
| 为什么这是一个**读数**的缺陷而不是一个措辞的缺陷？ | 因为**它印出来的东西一模一样**。docs 172 那次 `COST-MEASURED 3.5 °C` 就是这个形状：一个**真实的数字**、一个**真实的仪器**、一个**假的资格**。文档里那句话只是**这个缺陷的可见部分**。 |
| 修法是什么？ | 前提**在写任何东西之前从设备上读出来**：keeper 在不在，以及**有没有核还钉在镜像的 `performance` 上**。读出来的四个状态各自决定 A/B 怎么走（§3）。读数走的是 `--status` **同一个** device-side 程序（docs 165：两份拷贝就是这个文件里三个缺陷出现两次的原因）。 |
| 门在哪儿？ | 在 `--ab-anyway` 之前、在**仪器被 scp 上去之前**：`already-fixed` 和 `unknown` **拒绝测量**，状态记为 `premise`，**这个 boot 上不存在读数**（不是"测了但没测到"，是**没测**）。`baseline` 和 `partial` 照走。 |
| 为什么 `partial` **不**被挡？ | 因为一半在里面时，那个差**仍然带着还在外面的那一半**的价钱——把这条读数一起扔掉是浪费。报告会**点名它不能替谁说话**（`PRE_PRICES` 是从读数**算**出来的，不是写死的两句话）。 |
| `--ab-anyway` 是什么？ | 允许操作者**推翻前提**，并且**读数会带着标签**——终端上**和** `06b-heat-ab.txt` 里都写着"这是**安装**的前后，不是任何一个修复的价钱"。写进归档里这一点是必须的：stdout 会消失，归档会被引用。 |
| 离线怎么被证明的？ | harness **215 → 261 条全绿**：新增一节 5c（四个状态 + 越权 + `--status` 两侧）、**第 16 个变异**（把门删掉，一个"已经修好"的 boot **照测**，漂移被记成一次测量）。**写它的过程中被自己的断言抓出三个缺陷**，每一个都让 scenario 在跑之前**看起来是绿的**（§6）。 |
| 设备现在怎么样？ | **在跑**（`33e80afe`，`18d1:d001`，RNDIS），`boot_id 2fbf9f8e-deea-4955-ad0c-6bddf0fb14f5`——和 docs 176/177 是同一趟启动。`--status` 在这一轮被真的跑过一次，读出来的是 **`already-fixed`**：这正是这一篇存在的理由。**这一轮没有写任何分区**，唯一一次 ssh 是只读的 `--status`。 |

## 2. 这句话是从哪儿来的，以及它为什么曾经是真的

`ab_start` 在链的**第 4b 步**被调用，位置在第 4 步（address-ownership proof）之后、第 5 步（退休 keeper）**之前**。
第 4b 步的注释里写着这件事的理由：

> The measurement starts HERE: after the proof has decided whether the keeper may be retired, before the
> first of the two fix steps […] Window A is therefore the state AFTER the netwatch swap and BEFORE either
> heat fix, which is the baseline the two named causes need.

这段话**关于顺序的**部分是**对的**，而且它一直是这条链的力气所在：一个 boot 上，
**先读窗口 A，再做两件修复，再读窗口 B**。问题出在最后半句的**推理**上：
"我们**在修复之前**测了 A" 被读成了 "**A 就是那台没有修复的手机**"。

这两句话**在 2026-09-26 之前**是同一件事——那时候修复是**一次性的动作**，你在一台**没有装过它们**的手机上
跑这条链，A 自然就是"没有修复的手机"。而**现在不是了**：`install-retire-debug-keeper.sh` 和
`install-cpufreq-governor.sh` 装的是 **unit**，而 unit 是**每一次开机都跑**的。
所以今天这台手机开机的状态**本来就是 `already-fixed`**，链在第 4b 步读到的窗口 A 是
**一台已经修好的手机**，第 5、6 步是**把已经在那儿的两个状态再装一遍**（它们幂等，而且各自会读回自己的写入，
所以那两半**仍然是核对过的**），窗口 B 也一样。

于是那条链会做一件**最坏形状**的事：它**不报错**、它的仪器**没坏**、它的书里**没有矛盾**，
它把一个**完全没有效应的**差值（两个窗口都是修好的手机）印出来，旁边那句
"window A is before either fix" 让读的人**有理由相信那是价钱**。

这就是 docs 172 记住的那次 `COST-MEASURED 3.5 °C` 的同一个形状——**一次真实的测量，一个真实的数字，
一个假的资格**。区别在于 172 那次是仪器的问题（比的是最热的 zone、比的是会换手的最大值），
这一次**仪器是对的**，错的是**它被允许说话的那句话**。

## 3. 前提是一个**读数**，它决定四件事

`pre_state`（链里新的一节，位置在 `--status` 之前）用的是 `--status` **同一个** device-side 程序，
问的是那两个它能问的东西：

| 读出来的 | 怎么判 | 链怎么做 |
|---|---|---|
| **`baseline`** | `keeper present` **且**有核还在 `performance` | A/B **照跑**。窗口 A 就是那台没修复的手机，这个差是**价钱**。 |
| **`already-fixed`** | `keeper: gone` **且**没有核在 `performance` | **A/B 不测**。状态记 `premise`，归档的**第一段**就写清楚：前提失败了、读出来的是什么、**为什么这个差值不能当价钱**，以及**什么实验能在这样一台手机上把它们重新定价**——**INVERSE 实验**：窗口 A 把两半**拆下来**（起 keeper、四个核放回 `performance`、第三种原因写 `sleep_disabled=1`），窗口 B 再把它们装回去。**这条链只装不拆**，所以它说出来但**不做**。 |
| **`partial`** | 一半在里面 | A/B **照跑**，报告说清楚 "window A 是**已经装了一半**之后的手机"，并且**点名**它替谁说了话不能替谁说话。 |
| **`unknown`** | 读回没回答（超时/被杀）或者解析不出来 | **A/B 不测**。理由写在归档里：**读不出来的前提不等于基线**。 |

`partial` 的两个例子是**同一条句子算出来的**，不是写死的两句：

```
keeper gone,    four cores still pinned  ->  these deltas carry at most the governor (cause 2)
keeper present, four cores interactive   ->  these deltas carry at most the keeper   (cause 1)
```

第一句的推理值得写下来：keeper 已经退休了，所以**它已经在这两个窗口里都发生过了**，
它在 A 里在、在 B 里也在，**它自己抵消掉了**——因此这个差**不可能**是它的价钱，
而 governor 还没有装，它是那个**跨在 A 和 B 之间**的东西。这就是 `PRE_PRICES` 的算法。

> **为什么"读不出来的前提"要被挡住，而不是当成基线往下走？**
> 因为一个链**唯一**能保证"窗口 A 是没修复的手机"的路子，是**它读到了**这件事。
> 读不到的时候继续测，链就退回到这一篇修掉的那句话上：**用位置代替读数**。
> 而 `--status` 和一次运行在**同一个 boot 上**可能给出不同的答案（一个 boot 里你可以手装一半），
> 所以它不能"多数时候对就行"。

## 4. 门在哪儿，以及它为什么在**那儿**

门的代码只有四行，位置是这一篇唯一真正的设计决定：

```sh
case "$PRE_STATE" in
already-fixed|unknown)
  if [ "$AB_ANYWAY" != 1 ]; then
    AB_STATE=premise; AB_RC=premise
    …
```

它在 **`ab_start` 里、在 `THERMAL` 的可读性检查之前**，也就是在**仪器被 scp 到设备上之前**。
这不是洁癖：**把仪器推上去本身就改变了设备**（多一个 `/tmp` 里的文件、多一次 ssh），
而这一篇的整个论点是"**没有资格的时候什么都不要测**"。所以拒绝发生在一个**还没有动过手机**的位置上，
归档里那一段的第一句就是 **"…and it was read off the device before the instrument was copied over"**。

**门只挡测量，不挡安装。** 这一条是硬的：前提是**读数**的前提，不是**修复**的前提。
`already-fixed` 的 boot 上第 5、6 步**照跑**（幂等，而且各自读回自己的写入）；
前提失败唯一取消掉的东西是**那个差值**。离线断言分开写着两件事：
`notwant 'zl1-thermal.sh' "$(cat "$ACT")"`（没有推、没有测）
和 `want 'install-cpufreq-governor' "$(order)"`（修复照装）。

## 5. `--ab-anyway`：允许越权，但读数**必须带着标签**

推翻一样安全检查的正确做法不是把它删掉，而是**让推翻本身可见**。`--ab-anyway` 越过那道门，
然后**两个地方**都写下这件事：

* **终端**：报告的 `done` 分支里，对齐那一行**按前提**分岔。`already-fixed` 走
  "ALIGNED in time, but window A was NOT the unfixed phone"，`unknown` 走
  "window A was NEVER CHECKED"——**两个不同的句子**，因为这两件事对读者意味着不同的东西：
  前者是"我知道那是什么"，后者是"我不知道那是什么"。
* **归档**（`06b-heat-ab.txt`）：`THE PREMISE FAILED AND --ab-anyway OVERRODE IT` 那一段。

第二处是这一篇里最容易漏掉的一处，理由是**这个仓库反复记过的**：**stdout 会消失，归档不会**。
一次 `--ab-anyway` 的运行产出的是一份**完全正常的 A/B**——完整的两个差值段、真实的数字、真实的仪器——
而它**唯一**的限定如果在终端上，那么引用这份归档的人**看不到它**。
所以标签写在归档里，而且写在 scp **之后**（scp 的输出去向是 `>`，写在它前面会被清掉——
这是写这段代码时现场发现的一个顺序问题，不是推理出来的）。

## 6. 写它的过程中被自己的断言抓出来的三个缺陷

这一节是这一篇里最值得留着的一段，因为**三个缺陷都属于同一类**：
harness 里的 scenario **在它们存在的时候是绿的**，而红的那些断言**恰好就是为它们准备的**。

**(1) 追加在 `exit` 后面的代码是死代码。** 我让两个 callee 的 stand-in **真的改变假设备**
（退休那个杀掉 keeper，governor 那个把四个核写回 `interactive`），写法是把几行 `cat >>` 到
stand-in 文件末尾。而 stand-in 的正文末尾是 `exit "$rc"`——**追加的每一行都不可达**。
抓出它的是这一篇最重要的那条断言：`keeper: gone` 和 `governors: interactive …`。
修法是把"设备钩子"变成 `callee()` 的**第三个参数**，写在 `exit` **之前**。

**(2) 那条断言当时**在别处**被满足了。** `want 'keeper: gone' "$OUT"` 在死代码还在的时候**是绿的**——
因为这条链的收尾**散文**里就有 `keeper: gone` 这个词（它在解释**结束状态是什么**）。
也就是说：**一个断言被解释文字满足了**，而它本该由**读数**满足——
同一份 $OUT 里 `INDEX.txt` 明明写着 `keeper: 4242`。
修法是把两行断言**锚在读回自己的前缀上**：`^ *\| keeper: gone$`。

**(3) 前提读回超时的那条路会**崩**。** harness 里 prem-unknown 那个 scenario 需要让前提读回**卡住**，
所以它设了 `FP_SLEEP_STATE=5`——而这个 harness 的 `sleep` 是个 **stand-in，默认立刻返回**
（90 秒的 settle 能在一秒内被测试，靠的就是它）。于是那条路**从来没有被走到**：
前提读回答得很及时，读出来是一个健康的基线，**门没有开过**。
打开它（`FP_REAL_SLEEP=1`）之后立刻暴露出**第二个**缺陷：`PRE_PRICES` 只在函数**尾部**被赋值，
而超时分支**提前 return**，于是 `set -u` 下这行报
`PRE_PRICES: unbound variable`——**链在它自己的报告函数里死了**，
**没有归档、没有 INDEX**。也就是说：**这条链为"读不到前提"准备的那个状态，
在真机上第一次出现的时候会杀掉整条链。**
修法是在声明处初始化 `PRE_PRICES=""`，并且在注释里写下**为什么**：
超时分支是**没人手动走过**的那条路，而这一节存在的理由就是它。

三条的形状是同一个：**一个 scenario 之所以是绿的，是因为它从来没有走到那个分支**——
和 docs 177 记的那条（fixture 的时钟一动不动，所以"回落到被问的秒数"是**唯一**被跑过的分支）
是同一件事，只是这次发生在**门**和**它自己的错误路径**上。

## 7. 离线：215 → 261 条，以及第 16 个变异

新增的**第 5c 节**跑的是**四个状态 + 越权 + `--status` 的两侧**：

| 断言 | 它要的是 |
|---|---|
| 一个 `already-fixed` 的 boot **照跑到底**（exit 0），`INDEX.txt` 里那一行是 **`premise`**，归档以 **`NO A/B WAS TAKEN`** 开头，**点名**它读到的状态，并且说清楚**INVERSE 实验**是什么 | 拒绝是**有话说**的拒绝，不是沉默 |
| **`zl1-thermal.sh` 没有出现在任何调用记录里** | 门在**仪器被推上去之前** |
| **两个修复步骤照装**（`install-cpufreq-governor`、`install-retire-debug-keeper` 都在顺序里） | 前提挡的是**读数**，不是**修复** |
| 一个真基线：A/B **跑了**、索引是 `0`、操作者被告知 "this boot starts UNFIXED"、并且**收尾的读回**（同一个程序、另一侧）显示 `keeper: gone` 和四个 `interactive` | **"步骤前读"和"步骤后读"是可分辨的**——这是前提这个问题的**全部内容** |
| 两个 `partial`：一个 governor 在外面、一个 keeper 在外面，报告里那半句**按读数换** | 那句是**算**出来的 |
| `unknown`：门照开，**没有推任何东西**，归档说 "an unreadable premise is not a baseline" | 读不到 ≠ 基线 |
| `--ab-anyway`：A/B 跑了，报告和归档都**带着标签** | 越权是**可见**的 |
| `--status` 在两种设备状态上各答一次，且**一个安装器都没跑** | 只读 |

**变异 (16) `abpremise`** 是这一篇的"这个 harness 能红吗"的答案：它把那四行
`case` 的模式改成一个**不可能匹配**的状态名，于是门**不存在**了。
它必须被抓住的方式**正好**是这件事的形状——
`want '^06b-heat-ab *0'`（一个已经修好的 boot 被**记成一次测量**了）、
`want 'tsens_tz_sensor8.*-5.5 C'`（漂移**被印成了价钱的形状**）、
`notwant 'NO A/B WAS TAKEN'`（而**没有任何地方**说前提失败了）。
第三条是关键：这个变异**不会崩**、不会报错、不会让链里任何一条内部断言变红——
它**只是把一个假的资格印成了一个真数字**。

另外，报告里那句**赚来的**对齐话术也被单独立了断言：
`ALIGNED, AND THE PREMISE HELD: window A was the phone before either fix (keeper present, governors image)`
必须在，而**旧的那句** `ALIGNED: window A is before either fix, window B after both`
必须**在任何地方都不再出现**——因为那句话正是"用位置代替读数"，而 5c 的 fixture 默认状态
（keeper gone、四个核 interactive，**就是这台手机今天的样子**）正是它假掉的那一种。

## 8. 设备状态，以及下一件事

* 设备**在跑**（`33e80afe-v63-usbd-disabled-rndis`，`18d1:d001`，RNDIS，`boot_id 2fbf9f8e-…`）。
* 这一轮**真的跑过 `--status`**，读出 `already-fixed`——也就是说：**今天直接跑 `--yes`，
  在新版本之后会得到一个 `premise` 状态的归档**（旧版本会印一张差值表）。
  这是这一篇**唯一一次**在真机上看到的读数，而且它是**只读**的。
* **②的价钱仍然没有**，而且现在有了一个更清楚的说明：在这台手机上，
  它**不可能**由这条链量出来，因为两个修复**都已经在每一次开机时装好了**。
  要重新定价需要的是 **INVERSE 实验**（拆下来再装回去），而那条链**只装不拆**。
  ④ 三窗口设计（docs 169/173/174）、⑤ 交替配对设计（docs 175）和均值读数（docs 177）
  与这条链**互不影响**：它们是**独立的仪器**，各自手工跑，各自有它们自己的前提说明。
* 这一轮**没有 flash、没有写分区、没有 reboot、没有跑 QDL**。
  归档里**没有**任何来自真机的 A/B 读数，因为这一轮没有跑过 A/B。

## 9. 这一页**不**声称什么

* **不声称②或者①的价钱。** 这一篇只修**资格**：它让链在**不能定价**的时候说"不能"，
  而不是把一个漂移数字印成价钱。**它没有让这条链变得能定价。**
* **不声称这套判断在真机上跑过。** 四个状态、越权、`--status` 两侧，
  **全部只在离线 harness 里跑过**（261 条）。真机上只跑过 `--status` 的**一个**状态。
* **不声称 `INVERSE` 实验可行或者安全。** 它被**写下来**（在归档和终端里）作为一种
  "在这样一台手机上要定价得做什么"的说明，而它**把两个修复拆下来**这件事本身
  （起 keeper、把四个核写回 `performance`、写 `sleep_disabled=1`）**这一轮一次都没做过**，
  也没在离线被证明过。写下来的是**方向**，不是**一条已经验证过的路**。
* **不声称 `premise` 这个状态不会再有别的入口。** 它现在只由 `already-fixed` 和 `unknown` 走到；
  如果以后有第三种"读到了但都不像"的读数，它会落进 `partial`（`*` 那一支），
  而**那一支是会往下测的**。这一条是这一节唯一的开口，写在这里免得下一次有人以为它闭合了。
