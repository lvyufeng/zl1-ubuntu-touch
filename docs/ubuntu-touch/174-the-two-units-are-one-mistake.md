## 1. 一句话结论

| 问题 | 答案 |
|---|---|
| 这一轮买到了什么？ | **两条缺陷的修法，和"它们是同一条"这句话。**两处都是**一个数用一种单位，去比另一把另一种单位的尺**：① 上界数的是**睡眠秒**，而每次采样自己还要花时间；② pre-hold 拿一条**速率**去比一把**位移**的尺。 |
| 上界那条有多具体？ | `--settle-back 240` 在设备上花了 **798 秒**墙钟。算法摆着：每次循环 `sleep 10` **加上** 一次 10 秒采样自己要走一遍 `/proc` 的约 23 秒——**一次循环约 33 秒**（其中仪器自己占 23 秒）。整趟 1009 秒≈17 分钟，而 `--status` 印的是"最坏 12 分钟"。 |
| 速率那条有多具体？ | pre-hold 的判据 `0.5 °C / 10 s` 是一条 **3 °C/分钟** 的门，而整个实验的分辨率是 **0.2 °C**——**150 倍**。所以它把一台正在以 2.4 °C/分钟移动的手机认证成了"站着不动"，而**那台手机随后移动了 4.1 °C**（docs 173 §6）。 |
| 修法一？ | 两条 hold 都按**时钟**计（`now_s()` 读 `/proc/uptime`，因为这块板子的 RTC 读 1970，而且一个会跳的时钟会让 hold 因为**和温度无关**的原因结束），并且**每个量过的出口都印出它花了多少**：窗口多少秒、hold 多少秒、以及"它要的睡眠"和"它实际花的时间"之差。 |
| 修法二？ | `--margin` 是**位移**（花在整趟运行上，这正是窗口 C 之前那个 wait 一直在测的东西），所以 pre-hold 给**一个区间**的额度是 `--margin × 区间 / RUN_SPAN`，而它判的是**刚才看到的移动外推到整趟是多少**。默认值下这个额度是 **0.012 °C**——比仪器自己的 0.1 °C 步进还小。 |
| 那 pre-hold 还能通过吗？ | **在这台手机上，基本上不能。**而这正是 docs 173 §6.1 的结论变成了**可执行的东西**：要改的不是尺，是**设计**——用 `A B A B …` 交替把漂移在**一阶**上抵消，而不是要求漂移不存在。**这一页不设计它**，它属于下一轮。 |
| 那这算不算把仪器改坏了？ | **不算，而且它在设备上更省时间**：现在**第一个区间**（约 30 秒）就能判出"这台手机量不了"，而不是把 300 秒的 pre-hold 加上 240 秒的 wait 跑满再拒绝；两条出口都**什么都不写**。 |
| 写的时候还发现什么？ | 一条**同类的**缺陷，在仪器自己身上：窗口的墙钟是累加在 **`$(run_window A)` 这个子 shell 里**的，所以账目第一版印的是 `0s in 0 window(s)`——**一个在子 shell 里累加的计数器不是计数器**（这一页 §4.3）。 |
| 离线怎么被证明的？ | harness **212 → 242 条全绿**，两个新场景 + 两个新变异；两个修法各自还有**静态断言**钉在源头。而为了让"上界数的是睡眠秒"这件事**能被看见**，fixture 必须先获得一种能力：**让它的采样真的花时间**（`FP_SAMPLE_COST`）——**采样不花时间的 fixture 里，睡眠秒和墙钟是同一个数**，这就是这条缺陷活了这么久的原因（§7）。 |
| 上设备了吗？ | **没有。**242 条检查全是对着假设备跑的。 |

## 2. 两条缺陷是同一条：单位

把两处放在一起，它们的形状是一样的：

| | 量的东西 | 拿来比的尺 | 中文 |
|---|---|---|---|
| 上界 | **睡眠秒**（`sleep` 走了多少） | 操作者以为的**墙钟秒** | "等 240 秒"里那 240 是**睡眠**，采样**另算**，而采样是这台设备上最贵的一段 |
| pre-hold | **一个区间里的速率**（两次采样之差） | 整趟运行允许的**位移**（`--margin`） | "站着不动"说的是**整趟的位移**，代码量的是**一个采样间隔里的速度** |

两条都不是"数字算错了"，而是**这个数和它要回答的问题不是同一种量**。所以两条修法也不是两个补丁，
而是**把两边的单位对齐**：上界换成**时钟**，判据换成**位移**。

**为什么这两件事必须在这一轮一起做**：它们不是并列的两条，是**同一把尺的两端**。修了上界之后，
hold 的时长才是真的时长；而"判据挂在时长上"这句话里的**时长**，正是修好之后那个数。
只修一条，另一条的结论仍然是拿一个数比另一把尺。

## 3. 缺陷一：上界数的是睡眠秒，而采样是另算的

docs 173 那趟的时间账单是**直接读出来的**，不是估的：

```
uptime 19861   pre.1   ← pre-hold 第一个采样
uptime 19895   pre.2
uptime 19919   win.A
uptime 19997   win.B
uptime 20860   最后一个 wait 采样
```

* pre-hold 用 20 秒就通过了（两次采样之间 34 秒，其中 `sleep 10`、其余是仪器自己）；
* wait 的 `--settle-back 240` **实际花了 798 秒**（20860 − 19997 ≈ 863 减去中间的窗口与 undo），
  也就是 **24 次采样 × 约 33 秒**；
* 整趟 **1009 秒**（≈17 分钟），而 `--status` 承诺的是 12 分钟。

**这条缺陷的代价不是"数字不好看"，是两个**：一是**操作者侧的一个谎**（他按 12 分钟安排一次开机，
而设备按 17 分钟走）；二是**观测者在场**——wait 的每一次采样里有 10 秒是 `sleep`、23 秒是仪器自己在跑，
而验收判据正是"手机自己动了多少"。**等它回来这件事本身在给被测对象加载。**

## 4. 修法一：按时钟计，并且把花掉的印出来

### 4.1 时钟

```sh
now_s() {
  zl1_u=$(awk 'NR == 1 { printf "%d", $1 }' /proc/uptime 2>/dev/null)
  case "$zl1_u" in ''|*[!0-9]*) zl1_u=$(date +%s 2>/dev/null) ;; esac
  printf '%s' "${zl1_u:-0}"
}
```

**为什么是 `/proc/uptime` 而不是日期**：这块板子的 RTC 读 1970-02-13（docs 173 §8），所以仪器印的
**每一个日期都是错的**；而 uptime 以正常速率前进，并且**从不跳变**。一个会跳的时钟（比如一个
NTP step）会让一条 hold 因为**和温度毫无关系**的原因提前或推迟结束——**用错的时钟和不设上界是同一种错**。
`date +%s` 只作为退路，而且它印出来的日期是错的这件事，正是它只配当退路的原因。

两条 hold 的循环条件因此变成：

```sh
while [ "$(( $(now_s) - PRE_T0 ))" -lt "$SETTLE_START" ]; do   # pre-hold
while [ "$(( $(now_s) - WAIT_T0 ))" -lt "$SETTLE_BACK" ]; do   # the wait
```

于是 `--settle-back 240` **就是 240 秒**，而那 240 秒里**包含**采样——上界不再是一个比它承诺的短三倍的数。

### 4.2 花掉的印出来

每个量过的出口（判词、`no-return`、`no-plateau`、空表）都调一次：

**形状如下**（数字是示例，因为这一趟自己的账目还是要等下一次上设备才会印出来）：

```
   WALL CLOCK: this attempt took 798s: 132s in 3 window(s), 646s in
   the holds. The holds asked for 240s of sleep and spent the rest waiting on the instrument
   itself, 23s per sample. Every bound above is in THESE seconds, not in sleeps.
```

`23s per sample` **不是常数**，是**这一趟自己量出来的差值** `(HOLD_WALL - HOLD_SLEEP) / HOLD_SAMPLES`；
hold 一次采样都没做的时候它印 `no sample was taken`，因为 **0/0 不是 0**。
`--status` 里那句"最坏 12 分钟"也改了：它现在说的是**墙钟**，并且说明"每个采样要另加仪器自己走 `/proc`
的那一段"（10 秒的采样实测约 13 秒，见 docs 173 §5）。

### 4.3 写的时候发现的第三条（同一个形状，在仪器自己身上）

窗口的墙钟第一版是这么算的：

```sh
BUSY_A=$(run_window A)     # run_window 里 WIN_WALL=$((WIN_WALL + ...))
```

**`$( )` 是一个子 shell**，所以累加器出了那个括号就没了——第一版印的是 `0s in 0 window(s)`。
改法是让窗口把墙钟**作为输出**交出来（`printf '%s %s\n' "$busy" "$wall"`），由一个**在顶层调用**的
`win` 去记账。这一条和这一页的两条是同一个形状的第三次出现：**一个量在它被读的地方不是它被算的地方。**

## 5. 缺陷二：pre-hold 是一条速率门

判据原来是一行比较：**两次相隔 `--poll` 的读数，每一条 zone 的差都 ≤ `--margin`**。把它写成速率：

```
   0.5 °C / 10 s   =  3 °C / 分钟
```

而这个实验保护的是什么：判词的门槛是 **0.2 °C**，唯一量出来过的同类效应（③）是 **5.5 °C**，
②大概是 **2 °C 量级**，一趟运行约 **10 分钟**。所以这条门允许的漂移是

```
   3 °C/分钟 × 10 分钟  =  30 °C        （分辨率是 0.2 °C —— 150 倍）
```

**它不是"阈值定得太松"，是"用错了量"。**"站着不动"是一个**关于整趟运行的位移**的说法；
而代码量的是**一个采样间隔里的速度**。两者只有在"漂移是恒速"时才等价——而**恒速漂移恰好是
唯一一种能完全通过这条门、又完全破坏实验的漂移**（docs 166 命名的第一个盲区的特例）。

## 6. 修法二：判据挂在**运行的时长**上

`--margin` 从此只有一种意思：**这台手机在一次运行里最多可以离开窗口 A 多远**，
超过它这个实验就分不出"是 governor 还是手机自己在动"。这是**位移**，而它**花在整趟运行上**——
所以一个区间能花多少，是它按比例的份额：

```sh
RUN_SPAN=$((SECONDS_WIN * 3 + SETTLE * 2 + SETTLE_BACK))     # 窗口 A 开始 → 窗口 C 结束
bar_of() { awk -v g="$1" -v m="$2" -v s="$3" 'BEGIN { if (s+0 <= 0) { print m; exit } printf "%.4f", m*g/s }'; }
PRE_BAR=$(bar_of "$PRE_GAP" "$MARGIN" "$RUN_SPAN")
```

而判的不是"这一个区间动了多少"，是**它外推到整趟是多少**：

**形状如下**（`0.4 C` 和发生在哪条 zone 取自 docs 173 那趟 pre-hold 的真实读数；`5.0 C` 是本轮判据的算术）：

```
   NO PLATEAU within 300s of wall clock: two readings 33s apart never agreed closely
   enough to price this run. The largest change it still saw was 0.4 C (signed
   0.4 C, on thermal_zone16 (tsens_tz_sensor15)) -- projected over this run's 415s
   that is 5.0 C, against the 0.5 C this experiment can attribute.
```

两个数都印出来（`0.4` 和它外推的 `5.0`），因为**前者是读数、后者是判词**，而读者要能自己算第二行。

`RUN_SPAN` 的定义在**参数解析之后**：第一版把它写在默认值旁边，于是用 `--seconds 1 --settle 0
--settle-back 0` 起的一趟运行仍然报 `run span 415s`——**一个在参数被读之前算出来的跨度，是默认值的跨度**。

### 6.1 这条修的**推论**：这台手机过不了它，而那是对的答案

把默认值代进去（`MARGIN` 0.5 °C、`POLL` 10 s、`RUN_SPAN` 415 s）：

```
   一个 10 秒区间允许 0.5 × 10 / 415 = 0.012 °C
```

**比仪器自己的 0.1 °C 步进还小。**也就是说：**任何在 10 秒里动了一格的手机都过不了这条门**，
包括 docs 173 那一趟（它 10 秒动 0.4 °C → 外推 16.6 °C）。

**所以这一轮真正的结论不是"把门调紧"，而是**：

> **这台手机在一次运行的时间尺度上永远不会"站着不动"，所以三窗口 A/B/C 设计在这台手机上是
> 量不出②的价钱的——除非设计本身把漂移消掉，而不是要求它不存在。**

这正是 docs 173 §6.1 写下的那句话，这一轮把它**变成了仪器可执行的行为**：
现在这台仪器在**第一个区间**（约 30 秒）就会说"量不了"，并且**什么都不写**。
而**仪器不说谎**这件事，比它印一个数重要——docs 172 那一趟就是印了一个数。

**它带来的操作面好处是具体的**：在它上设备之前，一次"注定要拒绝"的运行要花 300 秒 pre-hold +
240 秒 wait + 三个窗口；现在它在一分钟内拒绝并给出**外推值**，而那个外推值正是下一轮设计要打败的数。

**把漂移消掉**的形状是**交替配对**：`A B A B A B …`（同一条命令在两个 governor 之间来回切，
每个窗口短、交替很多次），于是**随时间单调的漂移在一阶上被抵消**；而且**配对之间的散布**
本身就是这个设计以前没有的东西——**噪声的一次直接估计**，而不是一条要求噪声为零的门。
**这一页不设计它**，它属于下一轮；这一页只留下**它非做不可**的理由。

## 7. 离线怎么被证明的：242 条检查，2 个新场景，2 个新变异

**先说 fixture 必须先获得的能力**，因为这是这一轮最重要的一条方法论：

> **采样不花时间的 fixture 里，"睡眠秒"和"墙钟秒"是同一个数。**
> 所以整条缺陷在 212 条检查下活了那么久——**没有一条断言能让被测的东西自己花时间。**

改法是在 instrument stub 里加一个数：`FP_SAMPLE_COST`，让每一次采样**真的睡 N 秒**，
于是被测的时钟能看见它（真实设备上那个 N 是 23）。

| 场景 | 造出来的手机 | 断言的是 |
|---|---|---|
| `slow-samples` | 采样每次多花 2 秒，`--settle-back 3 --poll 1` | 它只取 **1 个** wait 采样：`1 秒睡眠 + 2 秒仪器`**就是**它被给的 3 秒；并且印出 `asked for 1s of sleep and spent the rest` |
| `slow-drift` | 一个 3 秒的 run 上每 1 秒动 0.4 °C（**旧的速率门每次都会认证它**） | 判词 `NO PLATEAU`、**没有干预**、外推值印出来（`1.2 C, against the 0.5 C`） |

| 变异 | 把什么放回去 | 它必须被看见 |
|---|---|---|
| m14 | 上界重新数**睡眠秒** | 同一个 3 秒上界下取 **3 个**采样，而**这一趟自己的账目**印出 `13s against a 3s bound` |
| m15 | pre-hold 的尺回到 `--margin` 本身（即速率门） | `slow-drift` 那台手机会被认证为"holding still"，**于是干预照做**——代价不是数字，是对一台量不了的手机动了手 |

**两个修法还各自有静态断言钉在源头**（注释剥掉之后）：pre-hold 的 `PRE_WAITED` 用的是 `now_s`；
wait 的循环条件用的是 `now_s`；`PRE_BAR=$(bar_of "$PRE_GAP" "$MARGIN" "$RUN_SPAN")`；
`RUN_SPAN` 只定义一次、由设置算出；以及 `cost_line` 出现在每一个量过的出口。

**`plateau` 场景现在有两个新断言**，它们钉的是**算式**而不是措辞：
在一个 3 秒的 run 上，一个 1 秒区间的额度**必须**是 `0.1667`，而它通过时外推值必须是 `0.0`。
这两个数在 fixture 里是**确定**的（区间和跨度都是整数），所以它们是算式的证据，不是渲染的证据。

## 8. 这一页**没有**成立的东西

* **两条修法都没有上过设备。**242 条检查全是对着假设备跑的。§6.1 那句"在第一个区间就会拒绝"
  是**从算式推出来的**，不是量出来的——它需要在设备上用**一次只读的 `--status`** 或一次 `--yes`
  才能变成读数，而这一轮没有碰设备。
* **②的价钱仍然没有。**三次运行、三次都不是价钱；这一页没有让它更近，它让**下一步必须换设计**
  这件事更硬。
* **`no-plateau` 在真机上仍然没有被走到过。**在它被修之前，pre-hold 在真机上 20 秒就通过了；
  修之后它**应该**在第一个区间就拒绝，但那是下一趟的事。
* **交替配对只是一个候选。**它的噪声估计、配对数量、每对的窗口长度、以及"governor 切换本身是否
  引入扰动"**一个都没量过**；这一页只给了它非做不可的理由。
* **`0.012 °C` 不是一个测量。**它是 `--margin`、`--poll`、`RUN_SPAN` 三个设置的算术结果；
  它要说的是"这条门比仪器自己的步进还紧"，不是"这台手机的分辨率是 0.012"。
* **`--status` 里"最坏 13 分钟"仍然是算出来的**（300 + 三个窗口各约 58 + 两次 settle 40 + 240），
  而窗口那 58 秒里的 13 秒来自 docs 173 对**一个 10 秒采样**的测量。**一趟真实的运行还没有印过
  它自己的账目**——那要等下一次上设备。
* **设备时钟仍然是错的**（读 1970-02-13）。这一页把两条 hold 从它身上挪开了，但仪器**印的日期**
  还是错的，`/proc/uptime` 只是让**时长**变诚实。
* **跨重启的持久性仍然没量过。**

| 那个"上界" | 数的是**睡眠秒**（240 花了 798） | 数的是**时钟秒**，而且**每趟都印出花了多少** |
| pre-hold 的判据 | 一条 **3 °C/分钟** 的速率门（分辨率的 150 倍） | `--margin × 区间 / RUN_SPAN`，判**外推**——默认 0.012 °C |
| 这台手机能不能过 pre-hold | **能**（于是它移动了 4.1 °C） | **基本不能**，而这正是要换设计的证据 |
| 拒绝的代价 | 300 s pre-hold + 240 s wait | **约 30 秒**（第一个区间），仍然什么都不写 |
| 仪器自己花了多少 | 没有一处印过 | **每个量过的出口都印**（窗口 / hold / 每次采样） |
| harness | 212 条 | **242 条**（2 个场景 + 2 个变异 + 5 条静态断言） |
| ②的价钱 | 没有 | **仍然没有** |

下一步是**换设计**：`A B A B …` 交替配对，让漂移在一阶上抵消，并让**配对之间的散布**成为
噪声的估计——那时这把尺不再是"要求噪声为零"，而是"知道噪声是多少"。这一页给了它的理由，
没有给它形状。硬件清单上还没驱动起来的那几项（相机 app 上没上屏、GPS 一次定位都没有、
指纹的驱动编进了镜像但没刷）这一轮同样**一个都没有碰**。

**这一页要求的那件事已经做了，形状在 [`175`](175-the-alternating-pair-is-the-second-design.md)**：
`--pairs N` 跑 N 对（fix 窗口、pinned 窗口），**每对内部的顺序交替**，读数是每对之差的均值、
误差棒是这些差的散布——§6.1 说的"让散布成为噪声的估计"就是它的判词。而写它的时候发现，
**交替顺序是承重的**：每对顺序相同时，pinned 窗口永远比它的 fix 窗口晚一个窗口，于是均值里
带着**一个窗口的漂移**（离线可看：同一台假手机，2.0 °C 的效应会读成 3.00）。两条 hold 的修法
在那一页仍然生效，只是**配对设计不用它们**。
