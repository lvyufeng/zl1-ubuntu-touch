仪器自己这么说了，而**它是对的**。

**这一页同时记下这一趟暴露出的两个东西**：仪器里一条**指向不存在证据的消息**（第 4 节），
以及这个三窗口设计**没有命名过的第二个盲区**（第 5 节）。

## 2. 这一趟跑的是什么，以及它为什么值得跑

docs 169 写完的仪器**一次都没在设备上跑过**——它的判词、退出码、trap、读回、四道拒绝，
全部是对着一个假设备验证的。这一趟买的是**第一件只有真设备能回答的事**：
**那四道拒绝在这台机器上过不过**，以及**那个写到底会不会落地**。

过。而且不是"没报错"式的过：

```
   A. panic guard: all 1 download_mode parameter(s) read 0 -- a panic reboots, not EDL
   B. instrument: readable (/tmp/zl1-thermal.sh)
   C. cores:      all 4 are writable and offer both 'interactive' and 'performance'
   D. as installed: all 4 core(s) read 'interactive' -- the fix is in place (this is window A)
   C. write path: wrote 'interactive' back to all 4 core(s) and read 'interactive'
                  back -- writable in fact, and every core agrees on what it read.
```

拒绝 C 的最后一条**是设备自己说的**：内核确实提供 `interactive` 和 `performance` 两个值
（这一条在 docs 169 里是离线读的 `scaling_available_governors`，这里是在**真的写下去之前**又证明了一遍）。
窗口 A 也确实是装好的状态——**如果四个核里有任何一个不是 `interactive`，这一趟在写第一个字节之前就会退出**。

而这一次干预**是两向都读回过的**：写 `performance` 之后四个核读回 `performance`，
写 `interactive` 之后四个核读回 `interactive`。跑完在设备上复核：`boot_id` 没变，四个核是 `interactive`。
**仪器把它借走的东西还回来了。**

## 3. 判词是 `CONTAMINATED`，而这是仪器的正确行为

```
   the largest warming from A to B on any tsens zone: 6.8 C  (thermal_zone12 (tsens_tz_sensor11))
   and from A to C (the control, same state as A):   8.4 C  (thermal_zone9 (tsens_tz_sensor8))

   -> CONTAMINATED: B was warmer than A by 6.8 C, but C -- the SAME state as A -- is still 8.4 C
      above A. So the warming did not come back with the governor's state and was not caused by it:
      the phone drifted, or the load did. A statement about this RUN, not about the governor.
```

如果这台仪器只有 A 和 B 两个窗口，它现在会**印出 6.8 °C 并把它当作 governor 的价钱**。
控制窗口的全部意义就是让这件事**不能**发生，而它这一趟做到了：**它报出了一条对手机什么都没说的结论**。
这正是 docs 166 把第三个窗口写进设计里的理由，也是 docs 167 那次为什么那条读数是可信的
（那一次 C 回到了 0.0 °C、而且是**反方向**的 0.7–1.3 °C）。

## 4. 缺陷一：那句"整张表在 archive 里"指向一个**已经被删掉**的目录

38 个 zone 读到了，**只印出 12 行**，然后是一句：

```
   ... 26 more; the whole table is in the archive (it is one line per zone)
```

而那句"archive"指的是 `$TMP/deltas`，脚本开头就是 `TMP=$(mktemp -d ...)`、
`trap 'rm -rf "$TMP"' EXIT`，**没有 `--keep`，也没有印出路径**。
所以这句话把操作者指向一个**运行结束就不存在的目录**——**而这一趟因此真的丢了那 26 行读数**，
它们唯一的一份拷贝在那次 exit 里被删掉了。

这正是这个仓库反复写仪器去防的那类东西（一句话声称的证据不存在），
而它**是靠跑一次才发现的**：离线读这个脚本，`say` 那一行看起来完全正常。
修法有两个方向（都还没做）：把整张表印出来（38 行在一个手机终端上是完全可以承受的），
或者加 `--keep` 并把路径印在那句话里——**但"archive"这个词在没有 `--keep` 的运行里必须消失**。

---

## 5. 缺陷二：这个设计防的是"在 C 之前消失的漂移"，而这一趟的升温在窗口里根本不衰减

三个窗口在**最热 zone** 上的读数：

```
   A  40.9      B  47.7      C  48.0
```

三个窗口的 busy：

```
   A  0.81      B  0.54      C  0.82     (of 4 cores)
```

**负载没有变，而且 B（被钉住的窗口）的 busy 反而是三个里最低的**——
这本身就是仪器自己写明的理由：governor 改的是核跑的**频率**，而 busy 数的是**时间**，
所以这两个量**本来就不该同步**。于是"这一趟的升温是负载造成的"这个解释被这条读数关掉了。

剩下的解释里，最贴合形状的是**热质量**：干预把 SoC 加热了（B 比 A 高 6.8 °C），
而把四个核放回 `interactive` 之后，**45 秒不够把 7 °C 散掉**，所以 C 读到的仍是热的那台机器
（48.0 °C，甚至比 B 还高一点）。

**这就是设计的第二个盲区，而它没有被命名过。** docs 166/169 写下的那个盲区是
"一个正好在窗口 B 里冲高、到 C 消失的漂移，和这个效应在这套设计里无法区分"——
但这一趟发生的**不是**那件事：这里的升温**根本没有消失**，它整趟都在。
两者的后果不同：前者会**虚报**一个价钱，后者会让**判词永远停在 `CONTAMINATED`**，
即**一个只会说"我不知道"的仪器**。

**修法不是"把 settle 调大"**——那是同一个猜测往上抬一档，而且它只是把"多长才够"这个问题
从 45 秒挪到 120 秒。可判定的版本是：**在开 C 之前，等读数回到 A 的一个具名容差之内，并给这个等待设一个上限**
（`--settle-back N`，容差和上限都印出来），然后**把等了多少秒说出来**。
如果在上限里**没有**回来，那本身是一条**关于这台手机的读数**——
"这个干预的升温在 N 秒内不衰减"——而它**仍然不是**"governor 值 6.8 °C"。
这两种结果必须走不同的退出码，否则仪器又会把"我不知道"和"价钱是这么多"混在一起。

热时间常数应该先**量一次**再定上限：这一趟的数据够估一个下界（45 秒内没有可见衰减），
但真正的常数要一个专门的小实验（放回 `interactive` 之后每 5 秒读一次，看它多久回到 A）。

## 6. 这一页**没有**成立的东西

* **②的价钱还是没有。**这一趟没有量到它，也没有反驳它。说"governor 让这台机器热 6.8 °C"是**错的**，
  说"governor 对温度没有影响"**同样没有依据**——这一趟两者都没有测。
* **一趟、一个负载、一个环境。**环境温度、充电状态、屏上有什么，**都不受控**，
  这和 docs 167 的 5.5 °C 带的那组限定是同一条。
* **热时间常数没有量过。**上面那个"45 秒不够散掉 7 °C"是**对形状的解释**，不是一条读数——
  它要一个自己的实验（第 5 节最后一段）。
* **跨重启的持久性仍然没量过**（docs 168 就留着这一格）：这一趟没有重启。
* **设备时钟是错的**：它读 1970-02-13，所以仪器印出来的每一个时间戳都是错的，
  真实日期在存档的表头里（同一个缺陷 docs 100 记过）。这一条**不影响任何温度读数**，
  但它意味着**任何按时间戳对齐这台设备的记录都会错**。

## 7. 阶段位置

散热那三条：①和③都有读数，**②现在有过一次真机运行，而那次运行说"我不知道"**——
这比一个错的数字好，但它还不是价钱。这一趟买到的东西按重要性排：

| | 这一趟之前 | 这一趟之后 |
|---|---|---|
| 四道拒绝在真机上 | 只有离线 | **全过，而且是写之前的** |
| 写路径 | 只有离线 | **真机上两向都读回证明过** |
| ②的价钱 | 没有 | **仍然没有**（`CONTAMINATED`，这是诚实的结果） |
| 仪器的这句话 | "整张表在 archive 里" | **已知是错的**：archive 在 exit 时被删掉，丢了 26 行 |
| 设计 | 一个已命名的盲区 | **第二个盲区被这次运行指出**：升温不衰减时，控制窗口只会一直说不知道 |

下一步是**把这两个缺陷都修掉**（第 4、5 节），其中第二个的修法要先量一次**热时间常数**——
而这两件事**全部离线可做**，做完再上设备。硬件清单上还没驱动起来的那几项
（相机 app 上没上屏、GPS 一次定位都没有、指纹的驱动编进了镜像但没刷）这一轮同样**一个都没有碰**。
