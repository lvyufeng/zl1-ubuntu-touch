## 2. 这一趟跑的是什么

docs 172 把比较改成逐 zone、绝对、带符号，并在窗口 A 之前加了一条 pre-hold。这一趟是那个仪器
**第一次**上设备，也是 pre-hold 第一次在真机上跑。它跑了默认设置（pre-hold 300 s、wait 240 s、win 45 s）。

它买到的第一件事，是**争端的形状**：上一趟这台手机在同一段代码下印出了 3.5 °C，这一趟同一条路径
**拒绝**了，而拒绝的理由**被印在判词里**：

```
   IT DID NOT COME BACK within 240s: the largest difference from window A is 4.1
   BELOW window A's reading of the SAME zone (-4.1 C, on thermal_zone9 (tsens_tz_sensor8)).
```

**"BELOW"这个词是这一趟的全部价值**：上一版的 `(n - a) <= m` 在本趟这一行上是**通过**的
（4.1 低是负数），于是它会一路走到窗口 C，把那个 4.1 °C 的下降当成"控制窗口只高了 0.3"来讲。
这一版把它读成"没有回来"，并且说清是往哪边没回来。

## 3. pre-hold 在真机上的读数，以及它证明的东西

```
== the pre-hold -- is this phone holding still, before a window is read at all?
   Two readings 10s apart must agree on EVERY tsens zone to within 0.5 C before window A is
   read. Up to 300s.
   IT IS HOLDING STILL: after 20s, the largest change on any tsens zone in the last 10s
   was 0.4 C (signed 0.4 C, on thermal_zone16 (tsens_tz_sensor15)). Window A
   below is a STATE, not a point on a curve -- which is what makes B and C comparable to it.
```

**这台仪器第一次在真机上证明了"窗口 A 是一个状态"**：两次相隔 10 秒的读数，在**每一条** tsens zone 上
都一致到 0.4 °C 以内——比上一趟"每十秒掉 4.2 °C"好了十倍。**而 §6 说，0.4 °C/10 s 不是"站着不动"。**

## 4. 判词 `NO RETURN`，以及它为什么是这一次正确的答案

它拒绝的理由，逐条对得上这一趟的数据（下面 38 行表在存档的 A 节，全表）：

```
   zone       type                        A      B     B-A
   thermal_zone14 tsens_tz_sensor13        40.1   42.0   +1.9
   thermal_zone1 tsens_tz_sensor0          39.9   41.6   +1.7
   ...
   thermal_zone10 tsens_tz_sensor9         47.0   45.4   -1.6
   thermal_zone9 tsens_tz_sensor8          47.0   44.8   -2.2
```

* **A 的最热两条是 47.0 °C（`thermal_zone9` 和 `thermal_zone10`），而它们在 B 里掉了 2.2 和 1.6 °C。**
  其余 19 条 tsens **涨了 0.6 到 1.9 °C**。
* **wait 结束时，整机比 A 低 4.1 °C**，而那个"低"落在 `thermal_zone9` 上——**A 最热的那一条**。

所以这一趟的"最大的 B-A"是 **+1.9 °C**（在最凉的那些 zone 上），而**这台手机自己的移动是 4.1 °C**。
**仪器拒绝把前者印成后者**，这就是它的全部作用。

而它拒绝的方式也值得记：**窗口 C 没有被读**（"there is no control window in this run, so there is no
verdict to print"），所以**这一趟不存在"一个第三窗口可以拿来哄人"的数**。

## 5. 缺陷一：那个"上界"的单位是**睡眠秒**，不是**墙钟秒**

`--settle-back 240` 这一趟花了 **798 秒**（≈13 分钟）。算法在那里摆着：wait 的每一次循环是

```sh
sleep "$ADV"                                    # 10 s
sh "$THERMAL" --seconds "$ADV" --quiet > ...    # 10 s 的窗口 + 这台设备走 /proc 的时间
```

而这一趟的进程表说得很清楚：一次 `zl1-thermal.sh --seconds 10` 从起跑到落盘要 **约 23 秒**
（它要在窗口结束后遍历一遍 `/proc` 做逐进程快照）。所以**每次采样 ≈ 33 秒，24 次 = 798 秒**——
上界数的是**睡眠**，采样是**另算**的，在这台手机上大约是这个上界的 **3.3 倍**。

**后果是操作者侧的一个谎**：`--status` 印的是"最坏 12 分钟"，实际这一趟 17 分钟
（`uptime` 19861 → ~20870）。**整趟的时间预算不能按上界算**，而且 wait 越长，误差越大。

这条**不是**"数字不好看"：这一趟的 wait 之所以要跑满，是因为手机一直在动；
而手机一直在动的**一部分原因就是 wait 自己在采样**（每 33 秒里有 10 到 23 秒是仪器自己在跑）。
所以"等它回来"这件事本身在给被测对象加热/加载——**一个观测者在场的量**。

## 6. 缺陷二：pre-hold 是一条**速率门**，而它的阈值比这个实验的分辨率高两个数量级

pre-hold 的判据是：**两次相隔 10 秒的读数，每一条 zone 的差都 ≤ 0.5 °C**。把它写成速率：

```
   0.5 °C / 10 s   =  3 °C / 分钟   =  0.05 °C / 秒
```

而这个实验**保护的是什么**：判词的门槛是 **0.2 °C**（"two steps of the instrument's 0.1 C"），
唯一一次量出来的同类效应（③，阶梯）是 **5.5 °C**，而②大概是 **2 °C 量级**。一趟运行的时长是 **~10 分钟**。

**所以这道门允许的漂移是**：

```
   3 °C/分钟 × 10 分钟  =  30 °C        （而实验的分辨率是 0.2 °C —— 150 倍）
```

换句话说：**一条能让手机在整趟运行里移动 30 °C 的判据，被用来证明"这台手机站着不动"。**
这一趟就是它放过去的：pre-hold 读到 0.4 °C/10 s（**2.4 °C/分钟**）就说"holding still"，
而后面那 4.1 °C 的移动**正是这个速率的延续**（降温在趋近环境温度，所以速率在变小）。

**它不是"阈值定得太松"，是"用错了量"。**"站着不动"是一个**关于整趟运行的位移**的说法；
而代码量的是**一个采样间隔里的速度**。两者只有在"漂移是恒速"时才等价——而**恒速漂移是唯一
一种能被这个判据完全放过去、又完全破坏实验的漂移**（docs 166 命名的第一个盲区正是它的特例）。

### 6.1 那修法是什么（这一页只把要求写清楚，不动手）

要求是：**pre-hold 的判据必须挂在"这一趟要花多久"上，而不是挂在"两次采样隔多久"上。**
一句可判定的写法是：**认证的位移 ≤ 实验的分辨率**，即

```
   max_dev(两次相隔 T 的采样) ≤ MARGIN × T / (这一趟的时长)
```

而把默认值代进去（MARGIN 0.5 °C、整趟 ~600 s），**这条门就要求两次采样之间的变化小于 0.008 °C**——
**没有任何一台真机在 10 秒里能做到**。**所以这一轮真正的结论不是"把门调紧"，而是**：

> **这台手机在整个运行的时间尺度上永远不会"站着不动"，所以这个三窗口设计
> 在这台手机上是量不出②的价钱的——除非设计本身把漂移消掉，而不是要求它不存在。**

**把漂移消掉**的那个形状是**交替配对**：`A B A B A B …`（同一条命令在两个 governor 之间来回切，
每个窗口短、交替很多次），于是**随时间单调的漂移在一阶上被抵消**，而不是被等待或阈值挡住。
这一步**这一页不设计**，它属于下一轮；这一页要留下的是**为什么非改不可**：
三次运行，三次都死在同一个量上——**这台手机的自身移动比要量的效应大**。

## 7. 三次运行放在一起

| | 判词 | 它印了什么 | 它为什么那样 |
|---|---|---|---|
| 第一次（docs 170） | `CONTAMINATED` | 三个窗口的数，**没有价钱** | 45 秒的修法状态散不掉干预的热，C 比 A 高 8.4 °C |
| 第二次（docs 172） | `COST-MEASURED` **3.5 °C** | **一个价钱，而它是 artifact** | 比较单向、比最热的 zone、而 A 读在一条下降曲线上 |
| 第三次（这一页） | `NO RETURN` | **方向**（4.1 °C BELOW），**没有价钱** | 手机在整趟里的自身移动（4.1 °C）大过效应（1.9 °C 量级） |

**三次都指向同一个事实**：**②的效应在这台手机的噪声水平之下**——而这不是"没测出来"，
这是一条**关于②的读数**：**它小于这台手机在十分钟里的自身移动**。
把它说成"②值 3.5 °C"（第二次）是错的；说"②没有影响"也没有依据——**这一页两者都没有说**。

## 8. 这一页**没有**成立的东西

* **②的价钱仍然没有。**三次运行、三次都不是价钱。这一页给出的是**它为什么一直不是价钱**。
* **§6.1 的那条修法没有写、没有测、没有设计。**这一页只写下要求（门要挂在运行的时长上）
  和它的推论（这台手机在十分钟尺度上不会静止 → 三窗口设计在这台手机上是死路）。
* **"交替配对"是一个候选，不是一个结论。**它没有这一页之外的任何证据。
* **`no-plateau` 在真机上仍然不可达。**这一趟 pre-hold 用 20 秒就通过了，
  所以那个"唯一什么都不写的出口"**依然没有被真机走到过**。
* **一趟、一个负载、一个环境。**环境温度、充电状态、屏上有什么都不受控；而这一趟的
  `busy` 数（0.82 / 0.54 / 1.04–1.07）里**包含仪器自己在跑的那一份**，窗口长度又不一样
  （45 s 对 10 s），所以**这几个 busy 数不能直接互相比较**——它们是读数，不是对照。
* **热时间常数还是没有量到。**这一趟给的是"手机在 13 分钟里降了 4.1 °C"，那是**降温曲线上的两点**，
  不是常数。
* **设备时钟是错的**（读 1970-02-13）。它在以正常速率前进，所以 `/proc/uptime` 是这一趟的诚实时钟，
  而仪器印的每一个日期都是错的。
* **跨重启的持久性仍然没量过**：这一趟没有重启。

## 9. 阶段位置

| | docs 172 之后 | 这一趟之后 |
|---|---|---|
| 旧版在同一形状下 | 会印 3.5 °C | **拒绝，并印出方向** |
| pre-hold 在真机上 | 从没跑过 | **跑通了**（20 秒，0.4 °C/10 s）——**而它证的不是它说的那件事**（§6） |
| 那个"上界" | 按睡眠秒印 | **实测是墙钟的 3.3 倍**（798 s 对 240 s） |
| ②的价钱 | 没有 | **仍然没有，而第一次有了"为什么"** |
| 操作者的时间预算 | 12 分钟（按上界算） | **17 分钟**（实测），而且 wait 越长差得越多 |

下一步有**两件小的**和**一件大的**：小的两条是这一页的两个缺陷（把墙钟印出来；把 pre-hold 的判据
挂到运行的时长上），**都能离线做完**；大的一条是**换设计**——把漂移从"要求它不存在"改成"在一阶上抵消它"，
这一页给了它的理由，没有给它形状。硬件清单上还没驱动起来的那几项
（相机 app 上没上屏、GPS 一次定位都没有、指纹的驱动编进了镜像但没刷）这一轮同样**一个都没有碰**。

**两件小的都做完了**（[`174`](174-the-two-units-are-one-mistake.md)）：两条 hold 现在按**时钟**计（`/proc/uptime`），每个量过的出口都**印出它花了多少**；pre-hold 的判据挂到了**运行的时长**上（一个区间的额度是 `--margin × 区间 / RUN_SPAN`），所以它判的是"刚才看到的移动**外推到整趟**是多少"。默认值下那个额度是 **0.012 °C**——比仪器自己的 0.1 °C 步进还小，也就是**这一页 §6.1 的结论变成了仪器可执行的行为**：这台手机过不了这条 hold，于是它会在**第一个区间**就拒绝，而不再印出一个数。**这一页留下的那件大的（换设计）没有动**，而两条修法**都还没有上过设备**。
