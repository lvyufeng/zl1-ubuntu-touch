# 96 — 同一个瞬时快照里，温度有三种单位；而测温度的那个仪器把它们当成了一种

**日期**: 2026-09-23
**状态**: 纯离线的一轮（设备在 EDL，`05c6:9008` / port 3-3，与 `86`–`95` 同）。这一轮抓到并修掉的是一个**真 bug，而且它已经在真机上跑过**——`72`/`81` 里每一个温度数字都出自这段算术。`95` 把"回到设备前要跑的那条链"验了一遍；这一轮验的是**用户点名的四件事里"发烫"那一件唯一的仪器**，而它报出来的数字是错的。

**接续**: [`72`](72-the-heat-was-the-governor-and-a-debug-keeper.md)（两个热源与那次 A/B）、[`81`](81-the-heat-line-has-an-instrument-now.md)（把 A/B 做成脚本，以及它自己抓到的第一个 bug）、[`87`](87-the-container-memory-reading-was-the-whole-phone.md)（同一类"读数被读错"的错，也在这段代码的邻居处）、[`95`](95-the-first-commands-after-recovery-are-offline-verified.md)（可重跑 harness 这个做法本身）。证据原文在 `docs/ubuntu-touch/evidence/thermal-units-2026-09-23.log`。

## 2. 三种单位是怎么被发现的（以及为什么它一直没被发现）

`72` 的测量本身是可靠的：它把每个区的**原始值和解释**都抄下来了（§9："tsens_tz_sensor1..20 分度，490 = 49.0 C；pm8994_tz/battery 毫度，46923 = 46.9 C；msm_therm/quiet_therm/pa_therm*/emmc_therm 整度，47 = 47 C"），甚至专门写了"`sort -n | tail -1` 会挑错最大值"。**那一段是对的，而且一直是对的。**

问题是这段知识**只活在文档里**：`81` 把测量法做成脚本时，`zone_read()` 和 `zone_print()` 对每一个区都写 `/1000`——也就是把**所有**区当成毫度，而这恰好只对其中一族成立。这个 bug 从来没被发现，因为：

* `81` §4 的端到端验证跑在**宿主机**上，而 x86 的 `x86_pkg_temp` / `acpitz` **全是毫度**，除以 1000 是对的。宿主机的绿灯对这台设备毫无意义。
* 真机上唯一一次读数发生在 `72`，那一次是**手敲命令**（`cat .../temp` 然后人脑换算），人脑用的是文档里那张正确的表；脚本接手之后没人再用它读过一次真机。
* 而错出来的数字**看起来像结论**：0.6 °C 是个合理的温度，"最热：battery 42.5 °C" 也是个合理的句子。

这正是 `95` 那个 harness 存在的理由的同一种形状——一次性验过、不可重跑、而重跑会立刻现形。

## 3. 修法：一张表，两个方向都收口

### 3.1 表

```awk
function zl1_scale(type,   f, u) {
  zl1_known = 1
  if      (type ~ /^tsens_tz_sensor[0-9]+$/)                             { f = 100;  u = "deci-degC" }
  else if (type == "pm8994_tz" || type == "battery")                     { f = 1;    u = "milli-degC" }
  else if (type ~ /^(msm_therm|quiet_therm|pa_therm[0-9]*|emmc_therm)$/) { f = 1000; u = "degC" }
  else                                                                   { f = 1;    u = "assumed-milli-degC"; zl1_known = 0 }
  zl1_unit = u
  return f
}
```

`zone_read()` 现在每行吐 `名字=type:毫度:原始:标记:单位`，**下游每一处比较/相减/排序都在一个单位里做**。这就是为什么 `--ab` 那两段的字数变了而公式没变：差值本来就是"毫度减毫度再除以 1000"。

关键是**为什么必须是表**：一个 10 倍的错**落在任何合理的温度带里**——原始 580 当毫度是 0.58 °C，当分度是 58.0 °C，两个都是可信的数字。所以判据只能是 zone 的 `type`（那是注册它的驱动设的，也就是决定单位的东西），不可能是值本身。

### 3.2 表过期了要吵，不能静

```sh
  thermal_zone25 zs_temp                      41.5 C   <- type not in the unit table; assumed milli-degC (raw 41500)
  thermal_zone26 emmc_therm                40000.0 C   <- IMPLAUSIBLE as degC: raw 40000
   hottest: tsens_tz_sensor8 58.0 C  (raw 580 = deci-degC, of 8 zones; 2 flagged above; 1 implausible, left out of the pick)
```

* **不认识的 type** → 标 `assumed`（默认按 ABI 的毫度，但说出来），并在汇总里计数。新驱动出现时，它不会悄悄混进来。
* **标度不可信的值** → 落在 `[-40, 160] °C` 之外就标 `IMPLAUSIBLE`，印出**原始值**，并且**不许参加"最热"评选**——一个刚被这个脚本宣布不可信的数字不该决定答案。

这里必须说清这条守卫**不是**表的替代品：1000 倍的错它抓得到（47000 毫度当成整度 → 40000 °C），**10 倍的错它抓不到**（580 分度当成毫度 → 0.58 °C 是个可信温度）。所以真正的那道保险是**最热那一行把原始值和单位也印出来**：

```
hottest: tsens_tz_sensor8 58.0 C  (raw 580 = deci-degC)
```

一个读到这行的人**可以在脑子里验算**。旧输出恰好不让人做这件事。

### 3.3 两处同源：`0b` 之前第一眼看到的数字

`host/zl1-health-check.sh` 的自检里那一行也是同一个错：

```sh
# 改前：thermal_zone1 是一个 tsens 区，选它只因为 "1" 看着像个索引；除以 1000 → 0.6 C
[ -n "$t" ] && say "   thermal_zone1: $(awk -v m="$t" 'BEGIN{printf "%.1f", m/1000}') C" || say "..."
```

现在设备侧只回一行 `thermal=type:temp type:temp ...`（还是同一趟 ssh，不做设备侧算术），宿主机用**同一张表**换算，印最热的那个并带上原始值。两份表**不可能悄悄分家**——因为 harness 用同一批假区同时驱动两个脚本，断言两边得出同一个名字和同一个数值（§4）。

## 4. 三个 harness 之外的第四个

`host/zl1-thermal-selftest.sh`，**44 项**，全部第一次跑就过（修完之后）。做法与前三个一致：`sed` 只改**真脚本**的运行路径，跑那一份，断言**人读到的东西**（逐区表、`hottest:` 行、A/B 两段）、退出码、以及什么都没写。

假根树里有一件真机上没有的东西：**三种单位同时在**。这才能让算术可测。A/B 那个场景用的是 `72` 自己的数字，所以断言是"`72` 的结论在仪器里活过来"，而不只是"某个数变了"：

```
   thermal_zone8 tsens_tz_sensor8           -6.1 C   (58.0 -> 51.9)
   thermal_zone1 tsens_tz_sensor1           -5.5 C   (55.8 -> 50.3)
   thermal_zone24 quiet_therm                -3.0 C   (50.0 -> 47.0)
   thermal_zone23 msm_therm                  -3.0 C   (49.0 -> 46.0)
```

它顺带钉住了 `81` 自己抓到的那个 bug（`read_stat` 拿到一行而不是两行时必须**大声退出**），以及一个反向断言：输出里**不许**出现 `+0.0 C`、不许出现 `0.x C` 的 tsens 行、`hottest:` 不许是电池/PMIC。

### 4.1 顺手抓到的两个 A/B 缺陷

写这个 harness 的过程中，`--ab` 那两段现出两个真问题。它们和单位无关，是**语义**的：

**（1）逐进程段只走 B 的表。** 代码是"遍历 B 的 top 表、去 A 里查"：

```sh
    ' "$TMP/top.A" "$TMP/top.B" | sort -rn | head -"$TOP"
```

一个**变安静**的进程按定义就不在 B 的 top 表里，于是它**根本不会出现在输出里**——而这恰恰是这个模式存在的理由（"我刚停掉的那个东西到底停了没有"）。`81` §3 的文档写的是"只在 A 的 top-N 里出现的进程按 0 起算"，**实现和文档不一致**。修法是把 `END` 块改成遍历两张表的**并集**。现在：

```
       -166  keeper 812
         -6  sensorfwd 8885
```

**（2）排序方向。** 逐区段原来是 `sort -rn` 排**带符号**的差值，于是"最大的变化"如果在下降方向就会**排到最后**：`72` 那次 A/B 里最大的变化是 tsens 的 −5.5 °C，而电池漂了 −0.3 °C，两者一个在列表头一个在列表尾，取决于符号。现在两段都按**变化量的大小**排，方向由符号表达。这条改动让"哪一行最重要"和"变化最大"重新对齐。

## 5. 这一轮**不**证明什么

* **对设备的结论：零。** 设备整轮在 EDL。假根树里的 `/proc`、`/sys`、进程表全是编的。
* **这张表不是从驱动符号推出来的**，是从一次测量推出来的（558 = 55.8 °C、49 = 49 °C）。它覆盖这台设备**出现过**的六个族。如果哪天某个族以另一个名字报分度值，表会算错，而**温度带抓不到 10 倍的错**——那时唯一的防线就是最热那一行印出来的原始值，以及"新族要加进表里"这个约定。
* **`pa_therm0/1` 和 `emmc_therm`** 在 `72` §9 里是被归到"整度"那一组的，但真正被读到并抄下来的只有 `msm_therm`/`quiet_therm`。如果 `pa_therm` 那一组其实是分度，温度带会**大声**报出来（这正是 §4 场景 2 钉住的行为），但那一组的单位**仍然没有直接证据**。
* **A/B 的排序和并集**只在宿主机上的合成双窗口里验过，没在真机上跑过。
* 这一轮**不解决发烫**。它修的是"发烫有多热"这个读数。`81` §5 欠的三次测量（sensorfwd+sensors HAL 的热代价、governor 修复的开机生效、容器内存）**一条都还没做**，仍然要设备。

## 6. 复现

```sh
# 全部在宿主机上，只需要 /bin/sh、sed、awk、find
sh scripts/host/zl1-thermal-selftest.sh          # 44 项
sh scripts/host/zl1-thermal-selftest.sh --keep   # 留下假根树、改写后的脚本、桩目录供查看

# 单位这件事，单独看一遍（用的是设备自己的数字）
for z in /sys/class/thermal/thermal_zone*; do cat $z/type $z/temp; done

# 回到设备之后：这一条现在会印出原始值和单位
sh scripts/device/zl1-thermal.sh --seconds 60 --top 15
sh scripts/device/zl1-thermal.sh --ab --hold 30      # 中途只改一个变量，看第二半
```
